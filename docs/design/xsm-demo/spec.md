# XSM 데모와 문서 — 디자인 브리프

## User stories

Claude Code나 Codex를 써봤고 멀티 에이전트 시스템을 만들려는 사람이, 익숙한 세션들에 역할을 주고 장기 작업을 운영하는 모습을 본다. Fable 팀장이 계획과 진척을 관리하고 워커들이 직접 협업하는 장면에서 자신의 작업에 적용할 방법을 이해한다. 이어지는 문서에서 xsm 설치, 첫 협업, 팀 운영으로 연결된다.

초기 산출물은 요구사항 인터뷰 기록과 pen 디자인이다. 이후 사용자가 “구현 완수”를 요청해 실행되는 웹 데모와 문서를 작업 범위에 추가했다. 구현 범위와 검증은 [implementation.md](implementation.md)에 기록한다. 공개 배포는 포함하지 않는다.

## Acceptance criteria

- 데스크톱 첫 화면에 기존 Claude Code·Codex 세션과 자연어로 팀을 구성하는 시연이 보인다.
- Fable 팀장이 목표·계획·담당·진행을 관리하는 장면, 워커 사이의 직접 협업, 팀 간 조율이 디자인에 표현된다.
- 방문자는 관람을 기본으로 하며, 재생·정지와 장면 선택을 통해 흐름을 따라간다. 작업 수행이나 설정 과제를 요구하지 않는다.
- 각 시연 장면은 같은 주제의 문서 위치로 연결되며, 문서 화면에서도 해당 장면을 다시 볼 수 있다.
- TypeSafe의 시각적 완성도, 프로필의 터미널 에뮬레이션, Reason Network의 데모·문서 연결을 각각 어떤 부분에 반영했는지 기록한다.
- pen 원본과 주요 화면의 PNG 미리보기를 남긴다. 텍스트 잘림·레이아웃 경고를 확인하고 내보낸 화면을 눈으로 검토한다.
- 브라우저 시연은 재현한 예시임을 밝힌다. 설치·세션 생성·모델 선택·권한 동의가 역할 지시만으로 자동 완료되는 것처럼 표현하지 않는다.

## Edge cases

- 자동 재생을 멈춰도 현재 장면과 관련 문서를 계속 읽을 수 있다.
- 동작 줄이기 환경에서는 타이핑·창 이동 애니메이션 없이 동일한 내용을 보여준다.
- 모바일에서는 창들을 축소해 한꺼번에 넣기보다 팀장·워커·보드를 순서대로 읽게 한다.
- xsm이 제공하는 것은 통신과 공동 상태다. 계획과 진척 판단의 주체는 에이전트이며, 진척률은 예시 계획의 완료 항목을 기준으로 표시한다.
- DM, 보드, 사용자 승인을 서로 구분한다. 워커의 요청을 사용자 승인으로 표현하지 않는다.

## Constraints

- 기존 README·기능 문서와 미커밋 작업은 보존한다.
- 현재 제품 계약은 [README](../../../README_ko.md), [조직 모델](../../xsm/ORGANIZATION.md), [팀 안내](../../../skills/xsm/references/teams.md)를 근거로 삼는다.
- 추가 런타임은 0.6.0의 실험적 지원 범위를 따른다. 첫 시연의 주인공은 Claude Code와 Codex다.
- 모델 배치는 사용자가 제시한 활용법을 보여준다. xsm이 모델을 자동으로 고르는 기능으로 표현하지 않는다.
- 이번 디자인에서는 실제 모델 호출·메신저 연결·사용자 세션 변경을 실행하지 않는다.

## Shape

시연과 문서를 별도 목적지로 두는 구성, 장면별 설명과 시연을 한 흐름에 두는 구성을 비교했다. 이번 초안은 후자를 택한다. 첫 화면의 짧은 쇼에서 장면을 고르면 같은 장면의 문서로 이어지고, 문서에도 해당 장면을 다시 재생하는 작은 창을 둔다.

1. **첫 화면:** "All you need is a message channel."을 크게 쓰고 "The rest is done by agents."와 구체적인 설명을 붙인다. 터미널 시연과 함께 보여주며 설치는 자연어로 요청하도록 안내한다.
2. **팀 구성:** 사용자가 Fable 팀장에게 목표·완료 기준·역할을 말한다. 이미 켜져 있는 Claude Code·Codex 세션이 협업한다.
3. **직접 협업:** 워커가 상대에게 구체적인 질문을 보내고 답을 받아 실행한다. DM은 행동 요청, 보드는 현행 계획·담당·결정으로 보인다.
4. **장기 진행:** 시간이 지난 뒤 완료·진행·막힘 보고가 도착한다. 팀장이 보드를 읽고 의존성과 계획을 갱신하며 사용자에게 근거 있는 진척을 보고한다.
5. **복수 팀:** API·UI 팀장이 조율 팀에서 공통 계약을 합의하고 각 팀의 보드에 반영한다. 워커들은 수평 관계를 유지한다.
6. **문서:** 설치와 첫 메시지, 팀 구성, 계획·진척 운영, 복수 팀 운영을 같은 이야기의 다음 단계로 안내한다. 상세 명령은 기존 레퍼런스로 연결한다.

## Motion and document connection

- 기본 흐름: 팀 구성 → 직접 협업 → 계획 갱신 → 팀 간 조율. 각 장면은 한 번에 한 행동에 시선을 모은다.
- 타이핑은 사용자가 보는 자연어와 에이전트 답변에만 쓴다. 전송 상태는 짧게 나타나고, 읽어야 하는 본문은 즉시 표시한다.
- 선택한 장면 이름과 아래 문서의 제목·번호를 맞춘다. "이 장면의 사용법"은 해당 문서 앵커로 이어진다.
- 문서에서 다른 주제로 이동하면 재생 창도 그 주제의 장면을 보여준다. 사용자가 정지했다면 자동 재생을 재개하지 않는다.
- 시간 경과는 "다음 날" 같은 표지로 압축한다. 진척 변화는 계획 항목의 상태 변화와 함께 보인다.
