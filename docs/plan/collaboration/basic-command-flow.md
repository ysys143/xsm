# 기본 명령과 비동기 회신 수정·검증

2026-11-04. 사용자 승인 계획의 구현 및 검증 기록이다. 전체 완료 여부는
실제 하네스 여섯 종의 결과를 포함해 판단한다.

## 승인한 동작

1. Claude Code의 `/xsm publish`, Codex의 `$xsm publish`는 그 대화의 공개
   지시다. 동일한 승인을 다시 묻거나 명령을 세 번 실행하지 않는다.
2. `xsm discover jstack --table`을 지원한다. 저장소·이름·제목·작업 검색을
   `query`로 통일하고, 기존 `--work`의 제목·작업 필터는 유지한다.
3. 사용자가 저장소의 세션에 연락하라고 명시했고 완전한 발견 결과에 해당
   저장소의 살아 있는 상대가 하나면 그 대화만 선택한다. 이름이 다르거나,
   후보가 여럿이거나, 결과가 불완전하거나, 질문·취소라면 자동 승인하지 않는다.
4. 선택은 두 대화에만 결속한다. 발견 실패를 근거로 reach·link·join을 열지 않는다.
   공개는 메시지 권한이 아니며, 선택은 상대의 준비 회신을 대신하지 않는다.
5. “끝나면 알려달라”는 요청은 한 번 보내고 턴을 끝내거나 다른 일을 한다.
   실제 회신은 하네스 입력으로 받는다. 장시간 sleep/poll 루프를 만들지 않는다.
   `queued`에서 바쁨·읽음 여부를 추론하지 않고, JSON 공백으로 답변 여부를 판정하지 않는다.
6. Claude Code·Codex·Pi·OpenCode·OpenClaw·Hermes에서 실제 모델이 도구를
   실행하는 왕복을 각 1회 확인한다. 속도 비교·메신저 재검증은 포함하지 않는다.

## 실행 경계

- 기존 시험 대화 재사용을 사용자가 선택했다. Claude `ref:5f60ca`, Codex
  `ref:8e85bd`의 실제 신원을 확인하고 작업 중인 대화에는 입력하지 않는다.
- Codex 후보를 공유 데몬 PID만 보고 본 대화로 오인했던 판단을 바로잡았다.
  지정한 대화와 본 대화의 실제 ID는 달랐다. native `thread/read`로 지정 대화의
  `notLoaded`를 확인한 뒤 `codex exec resume`으로 그 대화만 일회 재개했다.
  새 대화는 만들지 않았고 작업 중인 대화에 입력하지 않았다.
- 개발 코드는 시험 세션에만 로드한다. 전역 설치·사용자 설정·훅 신뢰·결제 경로는 바꾸지 않는다.
- 모델은 기존 구독 경로만 사용한다. 공급자 한도 실패를 같은 경로로 반복하지 않는다.
- reference 참여자와 실제 하네스를 구분한다. fixture 전송·등록 검사는 실제 모델 왕복으로 세지 않는다.
- 실패·미실행 항목을 남기고, 여섯 종을 채우지 못하면 전체 미완으로 표시한다.

## 검증과 산출물

후크 입력부터 CLI/MCP·공통 서비스·보관·회신 결속·ACK까지 이어지는 회귀 검사는
`tests/test_public_command_flow.py`에 둔다. 실제 네이티브 신원 및 전송 부분은 fixture이며
실제 모델 검증과 별도로 보고한다. 잘못된 승인·불확실성 처리 다섯 건과 native 질문 답변 우선순위 한 건을 임시 복사본에
다시 주입해 각각 회귀 검사가 실패하는지 확인한다.

명령·출력·실제 하네스 결과와 남은 항목은
[검증 기록](../../../deliverables/basic-command-flow-20261104/README.md)에 둔다.

구현과 여섯 하네스의 기본 모델 왕복은 완료했다. Claude는 native idle 수신과 MCP 회신,
Codex는 passive 요청의 명시적 CLI 수신·회신, 나머지 넷은 owned native turn의
도구 송신·회신을 확인했다. 상대는 protocol reference 참여자이며 모든 native 쌍이나
여섯 하네스의 공개 동의 UI를 검증했다는 뜻은 아니다.
