# ADR-0015–0023 수용 조건별 구현·검증 계획

- 상태: 기존 62개 + ADR-0024의 8개 = 총 70개. 구현 진행·게이트 기록과 수용 조건 종결은 구분하며 전체 통과를 주장하지 않는다.
- [전체 계획](spec.md), [병렬 실행·게이트](execution.md), [기계 판독용 원본](plan.json), [Reason 비교 노트](../../references/reason.md).
- ADR-0024의 사용자 결정은 관련 제안보다 우선한다. [확정 설계](collaboration-contract.md)를 함께 대조한다.
- 아래 원문은 ADR의 수용 조건 전체다. 여러 절을 가진 조건은 세부 셀을 모두 확인한 뒤 통과한다.
- 완료 책임 단위가 구현과 조건별 증거를 모으며 P13에서 전체 통합 판정한다.
- 구현 경로 목록은 plan.json의 각 조건과 실행 단위에 있다. 새 테스트 모듈·runner는 구현 전 생성 예정이며 현재 실행 가능한 검사로 주장하지 않는다.

## ADR-0015: 6개

[ADR 원문](../../adr/0015-connection-intent-and-participation.md)

### A15-01 — P02

같은 저장소·linked worktree는 추가 질문 없이 기존처럼 왕복한다.

- 구현·확인: 같은 저장소와 linked worktree의 CLI/MCP 양방향 왕복.
- 실패로 잡을 반례: 불필요한 추가 질문과 별도 clone의 자동 편입.
- 수용 종결 선행: P02; 최종 통합 판정 P13.
- 종결 게이트: G02; 전체 통합 G13. 게이트 통과와 해당 조건의 실제 실행 증거를 함께 대조한다.
- 필요한 증거: 격리 fixture, 실제 하네스.
- 연결 발견: R04.

### A15-02 — P02

새 저장소 연결의 비동기 사용자 승인 원문이 요청에 연결되고, 정상 API로 승인 반영·연결·원 요청 전송까지 끝난다. 이전 S5 실패를 먼저 재현하고 같은 경로로 검증한다.

- 구현·확인: S5의 실제 비동기 답 채널에서 원문→승인→연결→같은 ID 전송→회신을 추적.
- 실패로 잡을 반례: 답 수집 누락·적용 후 crash·새 ID 재송신·승인 재요구.
- 수용 종결 선행: P02; 최종 통합 판정 P13.
- 종결 게이트: G02; 전체 통합 G13. 게이트 통과와 해당 조건의 실제 실행 증거를 함께 대조한다.
- 필요한 증거: 격리 fixture, 별도 프로세스/장애 주입, 실제 하네스.
- 연결 발견: R02, R04, R38.

### A15-03 — P02

승인 수집 어댑터를 끊으면 승인 여부는 unknown으로 남고 원문·복구 위치가 보인다. 기록 파일이 없다는 이유로 임의 문장을 승인하지 않는다.

- 구현·확인: 답 수집 어댑터 중단 시 unknown과 원문·복구 위치 확인.
- 실패로 잡을 반례: 최근 답 파일 부재를 승인으로 간주하거나 모델 입력을 실제 사용자 답으로 승격.
- 수용 종결 선행: P02; 최종 통합 판정 P13.
- 종결 게이트: G02; 전체 통합 G13. 게이트 통과와 해당 조건의 실제 실행 증거를 함께 대조한다.
- 필요한 증거: 격리 fixture, 실제 하네스.
- 연결 발견: R02.

### A15-04 — P02

거부·취소·추가 질문은 연결을 만들지 않는다. 늦은 유효 응답과 중복 응답은 0020 계약을 따른다.

- 구현·확인: deny·cancel·추가 질문·중복·늦은 답의 상태와 연결 유무 대조.
- 실패로 잡을 반례: 묵시적 승인·범위 변경 후 이전 답 적용.
- 수용 종결 선행: P02, P07; 최종 통합 판정 P13.
- 종결 게이트: G02, G07; 전체 통합 G13. 게이트 통과와 해당 조건의 실제 실행 증거를 함께 대조한다.
- 필요한 증거: 격리 fixture, 실제 하네스.
- 연결 발견: R03.

### A15-05 — P02

별도 부모의 두 워커가 승인된 같은 협업 범위에서 직접 조율한다. 부모의 수동 중계가 필요하지 않다.

- 구현·확인: 서로 다른 부모의 두 worker가 공통 허용 범위에서 직접 요청·회신.
- 실패로 잡을 반례: 부모에게 수동 중계를 요구하거나 parent_ref로 통신 거절.
- 수용 종결 선행: P02; 최종 통합 판정 P13.
- 종결 게이트: G02; 전체 통합 G13. 게이트 통과와 해당 조건의 실제 실행 증거를 함께 대조한다.
- 필요한 증거: 격리 fixture, 실제 하네스.
- 연결 발견: R05.

### A15-06 — P02

요청 하나에 대한 동의로 다른 세션·폴더·업무 권한이 추가되지 않는다. 철회·재개 시 수명 계약을 적용한다.

- 구현·확인: 동의 대상·업무·수명·generation과 철회/재개 후 권한 readback.
- 실패로 잡을 반례: 한 요청의 동의로 이웃 폴더·새 대화·다른 업무 권한 확대.
- 수용 종결 선행: P02, P05, P07; 최종 통합 판정 P13.
- 종결 게이트: G02, G05, G07; 전체 통합 G13. 게이트 통과와 해당 조건의 실제 실행 증거를 함께 대조한다.
- 필요한 증거: 격리 fixture, 별도 프로세스/장애 주입, 실제 하네스.
- 연결 발견: R04, R32.

## ADR-0016: 8개

### A16-01 — P03

같은 입력의 CLI/MCP 질문이 동일한 실제 답과 원 요청 ID를 반환한다. 영수증만 있는 반례는 성공 답변이 아니다.

- 구현·확인: CLI/MCP 질문에서 request ID·reply_to·실제 답 의미 일치.
- 실패로 잡을 반례: 전달 영수증이나 다른 요청의 회신으로 답변 완료.
- 수용 종결 선행: P03; 최종 통합 판정 P13.
- 종결 게이트: G03; 전체 통합 G13. 게이트 통과와 해당 조건의 실제 실행 증거를 함께 대조한다.
- 필요한 증거: 격리 fixture, 실제 하네스.
- 연결 발견: R11.

긴 작업을 맡긴 동안 발신 세션은 자기 일을 하고, 늦은 답을 중복 없이 회수한다.

- 구현·확인: 비동기 task 동안 발신자 작업을 계속하고 늦은 결과를 원 ID로 회수.
- 실패로 잡을 반례: 대기 해제 후 결과 유실 또는 task 중복 실행.
- 수용 종결 선행: P03; 최종 통합 판정 P13.

- 필요한 증거: 격리 fixture, 실제 하네스.
- 연결 발견: R12.

### A16-03 — P03

같은 기능 표에서 priority·wake·첨부·회신·결과 입력의 CLI/MCP 차이를 전수 확인한다. 미지원은 명시한다.

- 구현·확인: 공통 기능 표와 CLI/MCP 스키마·지침·실제 adapter 효과 대조.

- 필요한 증거: 격리 fixture, 실제 하네스.
- 연결 발견: R13, R15, R16.

### A16-04 — P03

샌드박스 Codex가 첫 답장부터 가능한 경로를 사용한다. CLI 거부 후 모델이 임의로 대체 명령을 찾는 과정을 기본 절차로 삼지 않는다.

- 구현·확인: sandbox Codex의 첫 답장을 MCP로 보내 실제 원 요청과 회신 추적.
- 실패로 잡을 반례: CLI 거부를 먼저 경험해야만 경로를 찾거나 sandbox 권한 확대.

- 필요한 증거: 실제 하네스.
- 연결 발견: R16.

### A16-05 — P03

자동 수신 능력이 사라지면 미독 안내와 회수 경로가 살아 있다. 도구 숨김 때문에 답을 영원히 못 읽는 경우를 재현한다.

- 구현·확인: 자동 수신 능력 하향과 cached tools/list에서 미독 조회·회수.
- 실패로 잡을 반례: 도구 숨김 뒤 영구 unread·복구 경로 소실.
- 수용 종결 선행: P03, P04, P10; 최종 통합 판정 P13.
- 종결 게이트: G03, G04, G10; 전체 통합 G13. 게이트 통과와 해당 조건의 실제 실행 증거를 함께 대조한다.
- 필요한 증거: 격리 fixture, 실제 하네스.
- 연결 발견: R12, R14.

### A16-06 — P08

후속 질문을 일반 세션과 serve 각각에서 실행하고 네이티브 세션 ID·기억 유지 여부를 대조한다. 한 경로의 성공으로 다른 경로를 통과시키지 않는다.

- 구현·확인: 일반/owned headless 각각 후속 질문의 native ID·이전 사실 기억·권한 대조.
- 실패로 잡을 반례: 한 경로의 기억 성공을 다른 경로에도 적용.
- 수용 종결 선행: P08; 최종 통합 판정 P13.
- 종결 게이트: G08; 전체 통합 G13. 게이트 통과와 해당 조건의 실제 실행 증거를 함께 대조한다.

### A16-07 — P03

수신 대기 중 취소·시간 초과·동시 답변·여러 부분 회신을 검사한다. 대기 종료가 상대 과제를 중복 실행하지 않는다.

- 구현·확인: timeout·cancel·여러 부분 reply·동시 final·양식 중 tool 호출을 ID로 분배.
- 실패로 잡을 반례: MCP 입력 유실·교차 신원·대기 취소의 task 취소/재실행 변환.

### A16-08 — P08

두 발신자가 같은 협력자에게 동시에 요청하고 각자 후속 질문을 보낸다. 문맥 공유 단위·직렬화·퇴출 후 기억 소실·독립 검토 격리를 각각 확인한다. 설정한 용량만큼 모두 작업 중일 때 새 발신자를 추가해 요청 유실·새 워커 즉시 회수·미실행 성공 답변이 없는지 검사한다.

- 구현·확인: 두 발신자/업무·문맥 재사용·직렬/병렬·퇴출·독립 검토·용량+1 관측.
- 실패로 잡을 반례: 새 요청 즉시 퇴출·문맥 오염·미실행 오류를 성공 outcome으로 반환.
- 수용 종결 선행: P08; 최종 통합 판정 P13.
- 종결 게이트: G08; 전체 통합 G13. 게이트 통과와 해당 조건의 실제 실행 증거를 함께 대조한다.
- 필요한 증거: 격리 fixture, 별도 프로세스/장애 주입, 실제 하네스.
- 연결 발견: R39.
