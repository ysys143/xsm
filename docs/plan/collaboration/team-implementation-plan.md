# 팀 소통 구현 계획

- 작성: 2026-10-30
- 상태: 계획. 착수 전.
- 대상: [ADR-0025](../../adr/0025-team-and-multi-recipient-dm.md), [ADR-0026](../../adr/0026-team-board-on-xsm-doc.md), [설계 메모](team-communication-memo.md)의 결정 D1–D33과 "구현할 때 풀어야 할 것", 이번 논의에서 드러난 결함 두 개.
- 범위: 위 결정 전부. 순서만 정하며 빼는 것은 없다. 각 단계의 "구현 전 확인"은 결정에서 따라오지 않는 세부라 착수 전에 사용자에게 묻는다.

## 1. 전체 순서

```
T0 결함 수정 ─────────────────────────────────────────────┐
T1 다중 수신 send ── T2 다중 수신 ask ──┐                 │
                                         ├─ T3 팀 ─┬─ T4 connect 통합
                                         │         │
T5 doc 보드 ── T6 결재 기록 ── T7 보드 알림 ─┤         │
                                         └─────────┴─ T8 인수인계
T9 S12 재실험 (독립. T7 확정 전에 결과가 있으면 반영)
T10 스킬·문서 최종 정리 ── T11 channel 제거
```

| 단계 | 내용 | 선행 |
|---|---|---|
| T0 | `ack` 토큰 형식, MCP "hook record 없음" 오류 | 없음 |
| T1 | 다중 수신 `send`(로컬·SSH·P2P) | 없음 |
| T2 | 다중 수신 `ask` | T1 |
| T3 | 팀: 저장·구성원·팀장·권한·팀 주소·승인·P2P 구성원·팀 DM 알림 | T1, T2 |
| T4 | `connect`를 구성원 둘인 팀으로 통합 | T3 |
| T5 | doc 보드: 항목 모델·항목별 렌더·마찰 감소·MCP 쓰기·사람 편집 감지·공통 경로·P2P 노드 동기화 | T3(보드는 팀에 딸림) |
| T6 | 결재 기록: `xsm_decide`를 보드 옆으로 옮기고 보드 항목이 ID로 가리킴, P2P 동기화 | T5 |
| T7 | 보드 변경 알림: 다음 턴 팀별 한 줄 요약, 세션별 끄기 | T3, T5 |
| T8 | 인수인계: 팀 소속·역할, 담당 항목, 미독 DM·답 대기 요청, 작업 맥락 | T2, T3, T5, T6 |
| T9 | S12 어려운 표본 재실험, 걸러 읽기 권장 여부 판단 | 없음 |
| T10 | 스킬·README·사용 안내 최종 정리 | T3–T8 |
| T11 | `xsm channel` 제거, ADR-0005 Superseded | T6, T10 |

P2P(D22)는 별도 단계로 미루지 않는다. 팀 구성원은 처음부터 다른 머신일 수 있으므로 T3·T5·T6이 각자의 P2P 부분을 함께 끝낸다.

## 2. 모든 단계에 공통인 완료 기준

1. 새 동작과 막아야 할 반례를 단위 테스트로 둔다. 새 검사는 막으려는 결함을 일부러 넣어 실패하는지 확인한다.
2. 전체 회귀를 Python 3.9와 3.14 양쪽에서 skip 0으로 통과한다.
3. 바뀐 코드의 커버리지 90% 이상(0.4.20 이후 관행).
4. 실제 세션 확인: Claude와 Codex 실제 세션 사이에서 그 단계의 사용자 여정을 한 번 이상 실행한다. 일회성 실행(`claude -p`, `codex exec`)은 xsm 세션이 아니므로 이것으로 대신하지 않는다(S10 교훈).
5. 시험 실행은 격리된 `XSM_HOME`과 런타임 홈에서 하고, 실행 전후 사용자의 실제 설정 파일 해시를 대조한다(S11에서 `codex exec`가 실제 `config.toml`을 바꾼 교훈).
6. P2P 부분이 있으면 두 물리 Mac(맥북·맥미니)에서 확인한다.
7. 그 단계가 바꾼 동작의 스킬·문서를 같은 단계에서 고친다. 설치기 허용 목록이 바뀌면 `install --refresh` 경로도 시험한다.
8. 협업 계획 원장의 동결 입력을 건드리면 원장을 다시 묶는다(`scripts/audit-collaboration-plan.py`).

## 3. 단계별 계획

### T0. 결함 수정

- `ack` 토큰 형식: 수신 안내(`xsm/receive.py` 394·668행)는 JSON 토큰 객체를 보여 주고 "xsm_ack에 넘기라"고 하지만, CLI `xsm ack`(`cli.cmd_ack` → `receive.ack_inbox`)는 토큰 값만 받는다. CLI가 같은 JSON 객체도 받거나, 안내가 CLI와 MCP 각각의 정확한 형태를 보여 주게 한다.
- MCP "hook record 없음": `codex-worker-2`에서 `xsm_ack`·`xsm_send`가 실패하고 CLI는 성공했다. 목록에서 그 세션의 권한 모드는 `mode?`였다(`registry.py` 1109·1128행의 메시지). 원인을 먼저 재현으로 확정한다. 후보는 MCP 서버가 훅 등록 전에 caller를 고정하는 경우, 0.5.0 갱신 전후로 서버와 훅이 어긋난 경우다. 샌드박스 Codex는 MCP가 유일한 경로라 우선순위가 높다.
- 완료 기준: 두 결함을 재현하는 테스트가 수정 전 실패하고 수정 후 통과한다.

### T1. 다중 수신 send

- 바꿀 곳: `cli` send 인자(대상 여럿), `send.send`(지금 `target_spec` 하나), MCP `xsm_send`의 `targets`, 원장, 수신 헤더, `abuse.journal`의 집계.
- 따라오는 설계:
  - 메시지 하나에 ID 하나, 수신자별 전달 ID. P2P `Gateway.prepare`는 요청 ID를 수신자 하나에 묶으므로 수신자별 전달 ID로 보낸다(ADR-0025 3).
  - 보내기 전에 수신자마다 범위를 판정하고, 허용된 수신자에게만 보낸 뒤 빠진 수신자를 결과에 적는다(D14).
  - 수신 헤더에 다른 수신자 목록을 싣는다(D15).
  - 종료 코드는 가장 나쁜 결과(D17). 수신자별 결과를 줄마다 출력하고 `--json`에도 담는다.
  - 트래픽은 메시지 하나를 1건으로 센다.
  - 로컬·SSH 원격·P2P 수신자가 섞여도 된다. `--resend`는 실패한 수신자에게만 같은 전달 ID로 다시 보낸다.
- 구현 전 확인: CLI 문법(대상을 여러 위치 인자로 받을지, 쉼표로 받을지), 수신자 상한.
- 완료 기준: 섞인 수신자(로컬 Claude·Codex, 범위 밖 1, P2P 1)로 보내 수신자별 결과·종료 코드·헤더의 수신자 목록·원장·트래픽 1건을 확인한다.

### T2. 다중 수신 ask

- 바꿀 곳: `questions.ask`·`expects_reply`·`record_reply`(지금 `record["target"]` 하나만 상관 회신으로 인정), `question-status`, MCP `xsm_ask`·`xsm_question_status`.
- 따라오는 설계: 요청 하나에 수신자별 답 칸. 수신자마다 상관 회신·늦은 답·부분 답·outcome을 따로 모은다. `--wait`는 모든 수신자의 답을 기다리되 받은 만큼 보여 준다. 답 ACK는 답마다 따로다.
- 구현 전 확인: `--wait`의 종료 조건을 "전원 답" 하나로 둘지, "첫 답"도 고를 수 있게 할지.
- 완료 기준: 세 수신자 중 하나는 늦게, 하나는 실패로 답하는 경우의 `question-status`와 재시작 뒤 회수.

### T3. 팀

- 새 저장: `~/.xsm/teams/<팀>/team.json`(이름, 구성원, 팀장, 생성 근거, 승인 기록, 세대). 구성원은 이름 단위(D26)이며 이름과 홈·머신으로 실제 세션을 찾는다.
- 새 명령과 도구: `xsm team create|add|remove|lead|list|show|mute`와 MCP 짝. 허용 목록 반영.
- 권한(ADR-0025 11·12): 팀 가입은 구성원끼리의 DM을 허용하는 별도 객체다. `config.scope_for`에 팀 판정을 더하되 pair로 전개하지 않는다. 같은 project 안의 세션은 팀장이 넣고 뺀다. 범위 밖 세션은 사용자 승인이 필요하며 기존 승인 수집(`consent`, MCP elicitation)을 쓴다. 동료의 메시지는 승인이 아니다.
- 팀장(D5): 지정과 교체는 사용자 승인. 팀장 지위는 권한이 아니라 역할이다(팀장이 아닌 세션에도 직접 지시 가능).
- 팀 주소(ADR-0025 2): `send`·`ask`의 수신자로 팀 이름을 받아 구성원으로 펼친다(T1·T2 위에 얹음).
- P2P 구성원(D22): 다른 머신 세션을 구성원으로 넣고, 구성원 목록을 P2P로 맞춘다. 받는 쪽은 수신 때 팀 구성원 여부를 다시 확인한다. 네트워크 멤버십은 팀 권한이 아니다.
- 팀 DM 알림(D23): 팀 이름으로 온 DM은 즉시. 세션별 팀 알림 끄기.
- 구현 전 확인: 팀 주소 문법(`#팀`, `team:팀` 등), 팀 이름의 유일성 범위(머신별인지 네트워크 전체인지), 구성원이 끝난 세션일 때 팀 DM이 어떻게 보이는지.
- 완료 기준: 같은 project 안 팀(팀장이 추가), 범위 밖 세션 추가(사용자 승인), 맥북·맥미니 세션이 섞인 팀에 팀 이름 DM과 ask, 팀 밖 세션에는 아무것도 열리지 않음.

### T4. connect 통합

- `connect`(ADR-0024)가 구성원 둘인 팀을 만들게 한다. 사용자 선택과 실제 상대의 상관된 성공 응답으로 핸드셰이크를 완료하는 계약은 유지한다.
- 기존 `collaborations/` 기록을 팀으로 옮기는 이전 경로와, 이전 버전 상대와의 호환.
- ADR-0024 문서에 구현 결과를 적는다.
- 완료 기준: 기존 connect 시험 전부가 새 구현에서 통과하고, 기존 기록이 팀으로 이전된다.

### T5. doc 보드

- 바꿀 곳: `xsm/doc.py`(지금 렌더는 대표 노드 하나와 열린 끝 목록), CLI `doc`, MCP.
- 따라오는 설계(ADR-0026 1·2와 S11b 결과):
  - 항목 모델: 노드가 속한 항목을 가진다. 항목별 최신 노드로 렌더하고, 같은 항목의 동시 노드는 덮지 않고 함께 표시한다.
  - `report` 태그 기여가 보드 전체를 차지하지 않게 렌더 규칙을 바꾼다(S11b 구조 손상 4회).
  - 쓰기 마찰: 태그 기본값, 빈 본문·잘못된 태그·없는 옵션의 오류를 고쳐 쓸 수 있게 안내(S11b 실패 46건).
  - MCP 쓰기 도구(샌드박스 Codex).
  - 사람의 직접 편집을 렌더 시점에 감지해 사람 노드로 받아들인다. 렌더 결과를 덮어쓰지 않는다.
  - 위치: `~/.xsm/teams/<팀>/` 아래. 이력은 노드가 맡는다.
  - P2P: 팀 구성원 머신끼리 노드를 맞춘다. 노드는 불변이고 이름이 겹치지 않는다. 구성원이 아닌 기기에는 존재도 알리지 않는다.
  - 기존 공동 산출물 용도(ADR-0006)는 그대로 동작한다.
- 구현 전 확인: 항목 지정 문법, 보드 렌더의 형식(항목 제목·담당·상태 표시), 사람 편집을 노드로 바꿀 때의 작성자 표시.
- 완료 기준: S11b의 시나리오를 새 구현으로 다시 돌려 구조 손상 0, 쓰기 실패 감소, 항목별 현재 상태가 렌더에 보이는지 확인. 두 머신 사이 노드 동기화와 동시 노드 표시.

### T6. 결재 기록

- `xsm_decide`가 결재를 지금처럼 `xsm channel`의 `decision`이 아니라 팀 보드 옆 보호된 기록에 남긴다. 에이전트는 이 기록을 직접 쓸 수 없다(현재 `decision` 보호와 같은 수준).
- 보드 항목이 결재 기록 ID를 가리키고, 렌더가 그 결재의 질문·답을 함께 보인다.
- 결재 기록을 보드 노드와 함께 P2P로 맞춰 원격 팀원도 확인한다.
- 기존 channel의 `decision` 기록을 새 위치로 옮기는 이전.
- 완료 기준: 팀장 세션의 `xsm_decide` → 보드 항목 → 다른 머신 팀원의 확인. 에이전트가 결재 기록을 위조하려는 시도가 거부된다.

### T7. 보드 변경 알림

- 다음 턴에 팀별 한 줄 요약("보드 A: 항목 3개 바뀜, 결재 1건")을 넣는다. 세션별 마지막 읽은 위치에서 바뀐 항목만 센다. 세션별·팀별로 끌 수 있다(D23).
- 수신 훅이 매 턴 읽는 비용과 요약 길이의 상한.
- T9 결과가 먼저 나오면 걸러 읽기 안내를 이 단계에 반영한다.
- 완료 기준: 여러 팀에 속한 세션의 요약, 끄기, 상한 초과 때의 동작.

### T8. 인수인계

- 사용자가 "OO한테 인수인계해"라고 하면 그 세션의 xsm 대화 위치를 OO가 물려받는다(D27): 팀 소속과 역할, 보드 담당 항목, 미독 DM, 답 대기 중인 ask(이후 답이 새 세션으로 가는 경로 포함), 작업 맥락 요약.
- 기존 `xsm/handoff.py`는 수신 메시지의 claim·ACK를 다루는 별개 모듈이다. 이름이 겹치므로 새 기능의 모듈 이름을 따로 정한다.
- 상세 핸드오프 문서 형식과, 받은 세션이 팀장이면 지시를 이어 하고 워커 보고를 받는 행동은 스킬로 안내한다.
- 이름 단위 구성원(D26)과의 관계: 같은 이름 재시작은 자동 이어받기, 다른 이름으로는 인수인계.
- 구현 전 확인: 인수인계를 하는 쪽이 끝나지 않고 남아 있을 때 그 세션의 지위, 진행 중인 원격 ask의 재지정 방식.
- 완료 기준: 팀장 세션을 다른 세션으로 인수인계한 뒤, 워커의 보고·늦은 답·보드 담당이 새 세션으로 가는지 실제 세션으로 확인.

### T9. S12 재실험

- 어려운 표본: 실제 길이의 항목, 목록으로 주지 않은 암묵적 전제, 단어가 겹치지 않는 관련 변경. 판정 기준은 사용자가 정한다(지난 기준은 제안값이었다).
- 결과로 걸러 읽기를 스킬에 권장할지 정한다(D32).
- 실행 원시 출력에 계정 식별자가 남지 않게 격리 프로필을 쓴다(S12에서 71개 파일에 계정 UUID가 남았다).

### T10. 스킬·문서 최종 정리

- "남을 움직이려면 DM, 모두가 알아야 할 사실이면 보드, 둘 다에 쓰지 않음"(D30).
- 기존 상태 파일(`PHASE.md` 류)을 따로 두고 동기화하며, 그 파일에 정본 위치를 알리는 안내(D31).
- 팀장과 결재 안내(D5·D6): 비용·외부 공개·범위 변경 같은 범주의 승인 안내.
- 인수인계 행동(D27).
- README·README_ko·`docs/xsm/README.md`·PROTOCOL·TESTPLAN, evals 추가(팀 DM, 보드 쓰기, 인수인계).

### T11. channel 제거

- 조건: T6에서 `xsm_decide`가 옮겨지고 T10 문서가 갱신됨.
- `xsm post`·`xsm channel`·`xsm_post`·`xsm_channel` 제거, 설치기 허용 목록과 워커 MCP 목록에서 제거, `install --refresh`가 남은 허용 항목을 정리.
- 기존 게시(두 머신에서 맥북 5건)는 제거 전에 사용자에게 보여 주고 처리를 묻는다.
- ADR-0005를 Superseded로 바꾼다.

## 4. 릴리스

T0–T11 전부를 0.5.1 한 번으로 낸다(사용자 결정 2026-10-30).

- 단계마다 브랜치와 PR로 `main`에 합치되, 플러그인 버전은 마지막에만 0.5.1로 올린다. 중간 단계가 `main`에 있는 동안 기존 플러그인 설치는 0.5.0을 그대로 쓴다.
- 0.5.1 릴리스 조건: T0–T11의 단계별 완료 기준을 모두 채우고, 릴리스 소스로 전체 회귀를 다시 돌린다. 릴리스 노트에는 channel 명령(`xsm post`, `xsm channel`, `xsm_post`, `xsm_channel`)이 제거된다는 것과 기존 게시의 처리 결과를 적는다.
- T9는 언제든 돌릴 수 있고, T7의 알림 설계 전에 결과가 있으면 좋다.

## 5. 위험

- **권한 확장**: 팀은 새 통신 권한이다. 범위 밖 추가에 사용자 승인이 빠지면 0.5.0의 "고른 대화에만 결속" 원칙이 무너진다. T3의 반례 시험에 승인 없는 추가, 동료 메시지를 승인으로 오인하는 경우, 끝난 세션의 이름 재사용을 넣는다.
- **이름 단위 구성원**: 같은 이름의 새 대화가 자리를 자동으로 이어받는다(D26). 의도치 않은 같은 이름 세션이 팀 권한을 얻는 경로를 시험한다.
- **P2P 동기화**: 팀 구성원 목록·보드 노드·결재 기록을 머신 간에 맞추는 것은 새 동기화다. 제명된 기기의 기록, 오프라인 중 바뀐 구성원은 ADR-0021의 동등 멤버 모델과 토론 문서의 반례(소급 게시, 철회 인지 전 복제)를 따른다.
- **쓰기 마찰**: S11b에서 doc 쓰기 실패가 46건이었다. T5에서 줄이지 못하면 에이전트가 보드를 피할 수 있다.
- **기능 표면**: 명령·도구가 늘어난다. 스킬 분량과 에이전트 판단 부담을 T10에서 다시 본다.
