# 워커 프로젝트 가입과 질문 경로 정리

2026-11-04 구현 기록. 사용자 승인 내용은 팀장의 승인된 범위 상속, 새 범위의 팀장 세션 확인, 진입 안내 간소화다. 기존 CLI와 MCP 호출 형식은 유지한다.

## 사용자에게 보이는 동작

- 팀장은 워커를 시작하고 등록을 기다린 뒤 `xsm_join(project=..., workers=[...])`으로 가입을 한 번에 처리한다. 등록된 ref와 Orca의 `term_` 핸들을 받는다. 등록 전이면 워커를 다시 띄우지 않고 같은 핸들로 재시도한다.
- 확인 질문은 팀장과 선택한 워커의 실제 프로젝트 루트를 나열한다. 승인 후 폴더 가입을 한 번에 저장하고 팀장과 워커를 연결한다. 워커의 개별 가입 질문은 없다.
- 이미 가입한 폴더는 후속 세션에도 적용된다. 연결된 워커의 새 프로젝트 요청은 팀장에게 한 번 전달한다. 팀장 종료 또는 폴더 변경으로 연결이 유효하지 않으면 대기 상태를 반환한다.
- 원래 프로젝트 가입은 폴더 단위다. 같은 루트의 여러 세션 중 한 세션만 탈퇴시키는 기능이 아니다. 그룹 탈퇴의 확인 질문도 대상 폴더를 표시한다.
- MCP 폼을 지원하는 클라이언트는 폼을 사용한다. 지원하지 않거나 표시되지 않은 경우 반환한 정확한 질문을 네이티브 질문 도구로 한 번 묻는다. 답변 후 같은 MCP 호출을 한 번 재시도하면 Claude 완료 훅 또는 Codex 원본 답변 읽기로 반영한다. UI 모양은 하네스에 따라 다르며 승인 상태와 재시도 절차를 공통화했다.
- 연결된 팀장이 터미널에 주입한 `[팀장이름 지시]` 형식은 사용자 답변으로 수집하지 않는다.
- 진입 힌트는 `<request or command>`로 줄였다. `list`, `whoami`, `help`를 먼저 안내하고 기존 `who`와 나머지 명령은 보존했다. `whoami`에는 가입 프로젝트와 연결된 팀장을 표시한다.

## 구현 경계

Orca 애플리케이션은 수정하지 않는다. XSM 등록 훅이 제공받은 터미널 핸들을 보관하고, 생성자 측 스킬이 등록된 워커들을 그룹 가입시킨다. 기존에 떠 있는 미연결 워커의 팀장을 이름만으로 추정하지 않는다. 그룹 가입으로 명시적으로 연결해야 한다. 새 대화 또는 폴더 이동 후에는 다시 연결한다.

가입 철회 뒤 과거 결정의 성공 결과를 다시 반환하지 않는다. 이미 적용한 결정과 실제 가입 상태가 다르면 새 사용자 요청과 새 `decision_key`를 요구한다. 완료된 워커 요청 이후 새 가입 필요가 생기면 별도 메시지로 다시 알릴 수 있다.

## 검사

검사 명령:

```bash
python3 -B -m unittest tests.test_worker_project_flow tests.test_scope_service tests.test_openclaw_schema tests.test_xsm.SkillLayoutTest tests.test_mcp_dispatch tests.test_protocol_decisions tests.test_native_consent tests.test_user_answers tests.test_answer_binding tests.test_open_consent
```

위 명령의 결과는 `Ran 198 tests in 28.461s`, `OK`(종료 코드 0)다. `git diff --check`도 종료 코드 0이다. 추가한 워커 흐름 검사는 13개다. 팀장 1명과 워커 2명의 격리 프로토콜 세션을 실제 저장소·결정 기록 경로에 연결해 일괄 가입, 거절, 워커 질문 부재, 팀장 요청 중복 방지, 철회 후 재시도, 폴더 변경, 네이티브 답변 복구를 확인한다. Claude 훅 입력과 Codex 원본 답변 파일은 시험용 입력이다.

임시 코드 복사본에서 일괄 가입 분기를 제거하거나 네이티브 재시도를 다시 거절하도록 바꾸면 각각 대응 검사가 실패했다(두 실행 모두 종료 코드 1). 실제 Orca 워커 창과 실사용 모델을 새로 띄운 UI 검사는 수행하지 않았다. 전역 설치·릴리즈도 이 작업에 포함하지 않았다.
