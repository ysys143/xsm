## 느려진 원인과 책임

속도를 늦춘 주된 원인은 코디네이터의 운영이었다.

1. **완료 대상을 움직였다.** 계획에 있던 필수 필드·정규형·수신 안내·권한 목록을 처음에 일괄 대조하지 못해 뒤늦게 작게 여러 번 보완했다. 이미 동작한 뒤에도 가정적 경계를 계속 검토해 동결이 늦어졌다.
2. **서브에이전트에 일을 쪼개 다시 보냈다.** 명확한 최종 입출력·검사 묶음을 먼저 주지 못했다. 모듈 작성은 빨랐지만 코디네이터가 후속 지시와 통합 왕복을 늘렸다.
3. **검증과 개발을 뒤섞었다.** 수정 중 검토와 전체 검사를 시작해 서로 다른 소스 상태를 설명하고 재확인하는 비용을 만들었다. 전체 회귀 자체는 3~4분 수준이다.
4. **게이트를 과하게 실행 진입 조건으로 썼다.** 안정된 계약에 대한 독립 구현까지 묶어 기다리게 했다. 검토 결과를 기술적으로 닫는 것과 별도 모델의 반복 판정을 받는 것을 혼동했다.
5. **실제 평가 설정을 처음부터 공장 설정과 맞추지 못했다.** 비기본 Codex HOME의 MCP 실행 환경을 빠뜨려 실제 모델 실행을 반복했다. 기존 installer의 환경 생성 계약을 재사용했어야 했다.
6. **중간 문서·설명을 과하게 늘렸다.** 최종 변경과 검증이 고정되기 전에 상세 이력을 반복 작성했다. 의사결정과 구현을 앞당기는 데 집중하지 못했다.

권한·응답 유실처럼 실제 재현된 결함의 수정은 필요했다. 늦게 발견하고 수정 범위를 계속 움직인 방식이 문제였다.

## 즉시 적용할 방침

### 1. 현재 B03을 닫는 작업에 고정한다

- 신규 ADR, 신규 목적의 API, UI 개선, 추가 플랫폼·혼합 버전 조합을 이번 종료 묶음에 더하지 않는다.
- 이미 정한 B03 종료 조건과 실제 재현된 차단 결함은 끝까지 처리한다.
- 종료 조건과 무관한 새 개선 제안은 소유 단계와 근거만 기록한다. 계획에 필요한 항목을 임의로 생략하거나 완료로 표시하지 않는다.
- 실제 실패·리뷰 지적 없이 가정만으로 구현과 검증 범위를 다시 넓히지 않는다.

### 2. 한 번에 배정하고 통합한다

- 서브에이전트 2개: 질문 계층과 디렉터리 계층. 코디네이터는 공유 연결·충돌·완료 판정 담당.
- 배정 시 API, 파일 소유권, 정상/반례, 종료 산출물을 한 묶음으로 고정한다.
- 수정 라운드는 현재 발견된 지적을 모아 한 번에 배정한다. 한 필드씩 후속 지시하지 않는다.
- 구현 슬롯 상한 3개는 유지한다. 완료한 에이전트를 대기 비용을 쓰는 새 조사로 돌리지 않는다.

### 3. 게이트는 관련 통합 판정을 막는다

- 선행 계약과 권한 경계가 안정돼 있고 알려진 차단 결함에 의존하지 않는 독립 구현은 검토·회귀와 병렬로 진행할 수 있다.
- 선행 게이트 미통과 상태의 소비자는 준비/구현 상태로만 기록한다. 필수 선행이 검증되기 전 통합 성공이나 게이트 통과로 세지 않는다.
- 알려진 신원·권한·원 ID 결함을 우회해 실제 사용자 상태에서 실행하지 않는다.

### 4. 검토는 묶고, 지적은 증거로 닫는다

- 주요 게이트의 Opus 5.5 검토 요구는 유지한다. B03의 G03·G05는 이미 받은 통합 검토를 사용한다.
- 게이트당 독립 전체 검토 1회. 자동 2축 검토와 전체 재검토 반복은 없앤다.
- 지적별로 재현·수정·영향 검사·필요한 변이 한 개를 결속하고 코디네이터가 닫는다. 별도 독립 확인이 필요하면 남은 해당 지적만 같은 맥락에서 확인한다.
- 검토 모델의 응답 대기를 전체 개발의 정지 조건으로 만들지 않는다. 단, 지적이 미해소면 passed로 표시하지 않는다.
- Opus의 1차 수정 필요 판정을 최종 통과 판정으로 바꾸어 인용하지 않는다.

### 5. 코드를 동결한 뒤 최종 회귀한다

- 개발 중에는 영향 검사만 실행한다.
- B03 코드/지침을 고정하고 hash를 기록한 뒤 Python 3.9·3.14 전체 회귀를 병렬로 한 번씩 실행한다.
- 실패가 생기면 실패 경로를 먼저 수정·검증한다. 변경으로 무효화된 범위만 다시 확인하며, 최종 전체 회귀가 필요한 실질 변경이면 그 이유를 기록한다.
- 이미 통과한 실제 하네스 실험은 그 경로를 바꾼 변경이 없으면 반복하지 않는다. 설치 환경 차이는 먼저 버전·HOME·MCP 설정으로 진단한다.
- 문서와 상태 갱신은 최종 결과를 받은 뒤 한 번에 한다. 새 실행이 없는 상태 설명을 진행으로 세지 않는다.
