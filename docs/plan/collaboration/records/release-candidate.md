# 로컬 변경 검토와 복구 자료

이 문서는 미커밋 구현의 검토 자료다. 배포판이 아니며 P12 원격 제품 통합, 실제 UI 관측, 전체 여정의 완료 판정은 남아 있다. 전체 진행은 [현재 체크포인트](current-handoff.md)와 [조건별 증거 색인](../completion-ledger.md)을 따른다.

## 사용 경로의 변경

- `discover`는 명시 공개 세션과 같은 Git repository의 폴더·워크트리 세션을 찾는다. 머신·업무·branch로 후보를 좁히고, 사용자가 고른 실제 대화에 `connect`로 핸드셰이크한다. 공개와 통신 허가는 별개이며 다른 후보의 권한은 바뀌지 않는다.
- `ask`는 요청 ID를 먼저 반환한다. `question-status`로 같은 요청의 실제 답을 회수하며, 대기 종료를 새 요청이나 작업 취소로 해석하지 않는다. 실제 답에는 가능한 경우 확인 토큰을 함께 반환하므로, 이미 읽은 답을 수신함에서 다시 찾지 않고 `ack`한다. 기존 `send --wait`는 전달 대기 의미를 유지한다.
- 수신함은 원문과 claim token을 함께 반환한다. 실제로 읽은 뒤 `ack`하며, 인계 중 프로세스가 종료돼도 미확인 원문을 다시 회수한다. 받은 메시지의 텍스트나 표시 이름은 사용자 승인이나 실행 권한이 아니다.
- CLI 첨부는 호출자가 읽을 수 있는 파일의 사본을 만든다. MCP는 호출자가 이미 읽은 내용만 받는다. 수신자는 `files`로 고정된 사본을 읽으며 원래 경로를 열거나 덮어쓰지 않는다.
- 명시적으로 만든 `owned` 런타임은 발신자·업무별 대화를 유지한다. overload·대기 취소·native 종료를 구분하고, 저장된 답은 모델 재실행 없이 조회하거나 재송신한다.
- 설치·진단은 설정 쓰기, 런타임 로딩, 실제 첫 왕복을 나눠 표시한다. 설정 파일에 도구가 있다는 이유만으로 수신 능력을 확인했다고 표시하지 않는다.

CLI와 MCP의 상세 인자는 [공통 메시징 안내](../../../../skills/xsm/references/messaging.md)에 있다. 신규 traffic 정책의 기본값은 observe다. 이번 구현이 전역 차단 기준이나 새로운 원격 backend를 활성화하지는 않았다.

## 확인 범위

[최신 로컬 결과](../../../../deliverables/p13-live/doctor-privacy-v2-regression.json)는 기존 설치·회신·수신 개선과 doctor 원문 노출 수정을 포함한다. Python 3.9.6의 1700개/435.648초와 Python 3.14.6의 1700개/319.740초 모두 OK이며 skip0이다. 고정본315파일과 관련135개 primary의 hash를 확인했다. 첫1700 full의 테스트 홈 fixture 오류와 정정, 이전1697 및 그 이전 결과를 각 source 이력으로 보존한다. 제품 delta의 actual Opus5.5 검토와 postfix 실제CLI 검증도 완료했다. 원격 제품 통합과 실제 UI 성공은 이 검사에 포함되지 않는다.

실제 native 증거는 Claude/Codex의 첨부 읽기·회신, 서로 다른 Codex 홈과 부모의 직접 협업, 질문 뒤 독립 작업을 마친 다음 같은 ID로 늦은 답 회수, 수정본과 옛 사본의 별도 검토, owned 대화 기억·동시 실행·저장 답 회수, 살아 있는 구버전 MCP를 보존한 업그레이드를 포함한다. 각 실행의 설정 보정·지원하지 않은 셀·실패와 원인 미확정 프로필 drift는 원 보고서에 남아 있다.

## 진행 중 요청의 복구

| 상황 | 복구 경로 | 보존할 것 |
|---|---|---|
| 질문 대기 종료 또는 응답 유실 | `question-status ID`; ID를 모르면 인자 없이 자기 요청 목록 조회 | 원 요청 ID·본문·대상 |
| 수신 인계 뒤 종료·취소 | 다음 수신함에서 미확인 원문을 회수하고 실제 읽은 token만 `ack` | 원문·claim 상태 |
| 사용자 질문 화면의 대기 종료 | `decision-status ID`로 상태 확인; 같은 의도는 같은 `decision_key` | 원 질문과 결정 ID; 만료·거부를 승인으로 바꾸지 않음 |
| 첨부 송신 재개 | 반환된 `manifest_id`와 원 요청을 재사용 | 고정 사본; 변경된 원본을 같은 요청에 다시 찍지 않음 |
| owned overload | capacity가 생기면 같은 ID·본문으로 `run` 재개 | 발신자·업무 context |
| owned 출력은 저장됐으나 전달 불명 | `status`·`reconcile`로 확인하고 `retry`로 저장 답 재송신 | native conversation·저장 결과; 모델을 다시 실행하지 않음 |

## 설치 해제와 이전 버전 복귀의 경계

현재 작업은 전역 설치를 바꾸지 않았다. 검토를 되돌리기 위해 사용자 작업 트리를 초기화하거나 기존 세션을 종료할 필요는 없다. 변경 파일과 새 파일을 분리한 Git diff가 검토 대상이다.

추후 승인된 설치의 해제는 `uninstall --claude-home HOME` 또는 `uninstall --codex-home HOME`으로 해당 홈을 지정한다. 해제기는 자신이 추가한 항목을 추적하며, 사용자가 바꾼 설정과 다른 홈의 설치를 보존한다. runtime 사본은 남는다. 이전 사본을 사용하는 MCP·reader·native 세션이 살아 있으면 그 사본을 제거하지 않는다.

이전 버전으로의 복귀는 검증된 이전 source/runtime에서 해당 홈에 설치하고 설정 readback과 실제 왕복을 다시 확인하는 작업이다. CURRENT 문자열만 되돌린 것을 전체 롤백 성공으로 세지 않는다. 새 사본·요청 journal·첨부를 일괄 삭제하지 않으며, 진행 중 요청은 위 경로로 조회한다. 실제 프로필 전체의 제거·롤백과 원격 서비스 회수는 아직 전수 검증하지 않았다.
