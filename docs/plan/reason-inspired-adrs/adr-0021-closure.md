## A21-01부터 A21-07까지의 증거

아래 7조건은 각 기록의 범위에서 종결한다. 표의 E 번호는 실행별 실제 기록을 가리키며 서로 다른 동결본·환경의 증거를 하나의 실행으로 합치지 않는다. 경로는 각 요청·응답의 실제 connection 관측을 우선하며, 전역 relay 연결 여부나 광고 주소만으로 본문 relay 경유를 판정하지 않는다. 같은 호스트, 두 물리 Mac, 실제 다른 NAT, FILE actor, 실제 모델 여정을 구별했다.

|---|---|---|
| A21-01 | E1의 제품 CLI 가입·양방향 ping은 두 Mac의 LAN direct와 Tailnet 주소 사용을 확인했다. E2의 공개 relay 및 UDP 차단·HTTPS CONNECT proxy는 각 2회, 총 4회 응답 모두 실제 `relay`, TLS origin·본문 digest 일치다. ## 공통 비교 종결과 유지하는 한계

[최종 비교 보고](../../../deliverables/adr0021/comparison-20261030/report.md)와 [집계 JSON](../../../deliverables/adr0021/comparison-20261030/summary.json)은 A21_03_complete=true·closed_with_recorded_limits·missing_cells=[]다. 과거 A/B-spike/C/D의 native 15회·cached 5회, 각 설치/시작/가입·추가 개입 수, A·D 실제 최초 연결 실패, C의 무SSH 업무, 새 B의 준비·복구·업무·회수·소유 제거를 구별했다. 실제 업데이트/키 회수/라이선스 비교 항목을 유지하고 숫자가 없는 비용은 미계측으로 남겼다.

종결한 세부 공백은 E14의 기존 소속 가입 응답 유실·전환/복귀, E16의 실제 private 설치·명시적 stop·uninstall·잔여 확인, E17의 최신 실제 math·actor 개입/재개·재시작 회수다. ccc3의 양 Python 전체 1936개 OK·skip 0과 지정 delta Opus 승인까지 확인해 이 문서의 실제 대기 셀은 없다.

다음 제한은 기록에 남으며 성공 범위를 넓히지 않는다.

- A21-01: proxy·자체 relay 일부는 같은 호스트 제품 서비스이며 자체 relay는 loopback HTTP 개발 조건이다. SSH 표본은 기존 관리자 SSH의 현재 서버 프로토콜이고 전용 forced-command 설치 성공이 아니다. 실제 다른 NAT는 Mac/Android 기존 멤버 이동 뒤 relay 왕복이다.
- A21-02/06: 두 물리 Mac·FILE actor 정책 표본과 같은 호스트 3서비스·모델 0의 키 교체/연속 전환을 구별한다. 모든 반례를 매번 두 물리 기기에서 실행한 것으로 만들지 않는다. 네트워크 가입은 공개·협업·파일/실행 승인이 아니며 외부 계정 증명·hosted MCP 내부는 미검증이다.
- A21-03/04: 기존 SSH/Tailscale/구독 인증·제공물과 초기 등록 setup을 재사용했다. 최초 인증 전체·무보정 자동 wake·각 후보 업데이트 전수 성공은 주장하지 않는다. 최초 math 주제만 같고 후속/마지막 과제와 회수·시간 경계가 다르다. pure network latency·bootstrap 세부 시작·사람 판단 시간·provider 내부 스케줄링 및 숫자 없는 운영/업데이트/라이선스 비용은 미계측이다.
- A21-05: 실제 n0 relay 자체 중단 대신 소유 엔진 링크 차단으로 로컬 업무 독립성을 확인했다. 제거 뒤 runtime/state/key/원문·audit의 의도된 보존을 활성 소유 서비스 잔여와 구별한다.
- A21-07: AF_INET6 EAFNOSUPPORT는 실제 엔진 프로세스의 제어된 고장 주입이다. 실제 호스트 전체 IPv6 부재와 구별하며 원 interposer 실패를 보존한다.

이 문서는 ADR21의 7조건을 기록 범위에서 종결한 문서다. 다른 63조건·전역 G11/G12/G13, 전체 설치 행렬·라이선스 배포 승인·운영 배포의 판정을 변경하지 않는다. 실제 사용자의 D12 선택은 제품 방향 결정이며 실험 승인·실행 결과·정적 검토와 별개다.

코디네이터가 확인한 과거 전체 색인의 `audit --structure-only`는 최신 source hash 불일치로 exit 1이었다. 조건 29행 stale과 전역 카탈로그·결정·집계·통합의 5항목 한계 및 과거 1700개 snapshot을 보존한다. 기존 1915개 실패·1918개 통과·1933/1935개와 원 검토 판정도 당시 이력이다. 이번 ccc3의 1936개 통과를 전역 70조건·다른 63조건 완료로 올리지 않았고 과거 색인·원판정은 수정하지 않았다.
