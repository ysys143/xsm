# 발견·선택·핸드셰이크: 확정 설계와 구현목표

- 상태: 설계·구현목표 확정, 2026-10-28 사용자 결정. 제품 구현 완료 아님.
- 결정: [ADR-0024](../../adr/0024-discover-select-and-handshake.md).
- 기존 범위: ADR-0015–0023, P00–P13, 발견 R01–R43, 잔여 20개를 유지한다.
- 수용 조건: 기존 62개 + A24-01–08 = 70개. 원격 여정의 최종 판정은 G12/G13이다.
- 실행 목표: 전체 Reason 벤치마킹 구현 계획 완수(사용자 요청으로 일시정지). [개정 개발 방침](development-policy.md)의 마감·종료 절차를 따른다. 설계 확정 자체와 실제 설정 변경·외부 송신 승인은 구분한다.

## 원격 전송·멤버십 보완 결정

2026-10-29 [ADR-0021](../../adr/0021-cross-machine-network-and-membership.md)으로 자체 P2P·선택적 Tailscale 경로·공개 relay 기본/자체 설정·계정 비필수·기기키/초대 가입을 확정했다. 활성 기기 멤버 누구나 초대·기기 추가·제명을 할 수 있고 관리자 계층이나 별도 가입 승인은 두지 않는다. 최초 기기는 신뢰의 출발점이다. 이 결정은 아래 후보 공개·선택·협업 권한을 넓히지 않으며 P12 구현 완료도 아니다.

## 1. 사용자가 경험할 흐름

1. 사용자가 대상 세션에 “이 세션은 xsm에서 찾을 수 있게 공개해놔”라고 사전 지시한다. 같은 repository의 폴더·워크트리 세션은 이 별도 지시 없이도 후보가 된다.
2. 맥북의 에이전트가 “macmini에서 이 작업 하고 있는 세션 찾아와봐”를 수행한다.
3. 후보 a1, a2, b1, b3의 머신·업무·repository/branch·상태·관측 시각을 보여준다. 사용자가 작업을 확인한다.
4. 사용자가 “a1이랑 붙어서 일하자”라고 지정한다.
5. 에이전트가 선택된 실제 세션에 협업 의도를 보내고 신원·수신 능력·응답을 확인한다. 유효한 지시가 있으면 내부 project나 별도 폴더 연결을 다시 묻지 않는다.
6. 실제 상대 응답 뒤 핸드셰이크 완료를 알리고 작업 요청·회신을 이어간다. 나머지 후보와 새 협업은 시작하지 않는다.

## 2. 후보 집합과 공개 경계

`후보 = 명시적으로 공개한 세션 ∪ 같은 repository의 폴더·워크트리 세션`이다. 머신·업무 필터와 제외·차단 정책을 적용하고 실제 conversation 핸들로 중복 제거한다. 검색어가 맞는다는 이유로 후보 밖 세션을 공개하지 않는다.

명시 공개는 사용자 소유·허용된 머신/협업 환경 안의 검색 노출이다. 인터넷 공개나 팀·머신 신규 가입을 뜻하지 않는다. 자동으로 로컬 프로세스를 등록·공개하지 않는다. 같은 repository는 실제 repository 공통 근거로 판정하며 디렉터리명이나 Git remote URL의 문자열 일치만으로 다른 clone이나 원격 머신을 편입하지 않는다. 원격 동일성은 인증된 머신의 검증된 repository 매핑을 사용한다.

후보의 `discovery_basis`는 `explicit` 또는 `same_repository`이며 둘 다 해당할 수 있다. 공개 기록에는 적용 세션 신원·사용자 의사 출처·철회 상태를 남긴다. 공개 상태와 연결 상태를 하나의 boolean으로 합치지 않는다.

업무 확인에는 네이티브 제목·진행 중 할 일의 필요한 요약과 branch를 사용한다. 원문 전체·절대 경로·첨부를 새로 공개하지 않는다. 추출 출처·관측 시각·unknown을 표시하고 기존 bounded probe 예산을 공유한다. 추출 실패가 주소 발견이나 기본 통신을 막지 않는다.

## 3. 선택, 권한, 핸드셰이크

| 상태 | 근거 | 다음 동작 |
|---|---|---|
| 후보 발견 | 공개 또는 같은 repository, 필터 일치 | 업무 정보를 보여주고 사용자 선택 대기 |
| 대상 선택 | 특정 후보에 대한 사용자 협업 지시 | 지시 원문·대상 핸들·협업 의도를 요청에 결속 |
| 연결 확인 중 | 호출자·머신 인증·범위 확인 | 선택한 상대에게 같은 ID로 핸드셰이크 요청 |
| 상대 확인 대기 | 접수/전달만 관측 | 상대의 상관된 응답을 기다리거나 후속 조회 |
| 협업 가능 | 실제 상대 응답·신원·권한 유효 | 완료 알림과 양방향 작업 요청/회신 |
| 대기·실패·철회 | timeout/offline/대상 교체/해제의 직접 증거 | 상태와 회수 위치를 알리고 같은 요청에서 복구 |

이미 같은 repository 또는 기존 승인으로 통신할 수 있는 세션은 그 권한을 유지한다. 새 세션 협업 승인은 요청자·선택한 native conversation 한 쌍에 결속한다. 폴더 전체 link/join은 사용자가 그 범위를 명시했을 때의 기존 기능이다. 공개만 한 상대에게 자동 작업을 보내지 않는다.

핸드셰이크 응답에는 원 요청 ID, 응답하는 실제 conversation, 머신/런타임 신원, 수신 능력, 협업 의도를 확인할 수 있는 응답을 결속한다. 내부 세부 필드의 wire 형식은 기존 envelope와 호환되게 구현한다. peer ACK가 사용자 지시나 원격 머신 인증을 대신하지 않는다. 별도 parent/child 조건을 넣지 않는다.

모호한 이름이나 선택 이후 다른 대화로 교체된 대상은 조용히 바꾸지 않는다. 대화가 그대로인 resume은 실행 세대를 재검증하고 유효한 같은 승인을 재사용한다. 공개 철회와 협업 해제는 각각 적용하며, 별도의 기존 repository 권한이 남는 경우 그 근거를 구분해 표시한다.

## 4. 구현목표와 소유 단계

| 목표 | 담당 단계 | 출구 증거 |
|---|---|---|
| 선택한 세션에 결속한 협업 지시·권한 차이·동일 요청 복구 | P02, P07 | A24-04·07의 로컬 경로, 승인 출처·적용 결과 일치 |
| 실제 상대 답을 회수하는 질문/핸드셰이크 서비스, CLI/MCP 공통 결과 | P03, P04 | A24-05·06의 로컬 경로; 영수증만으로 완료하지 않음 |
| 명시 공개와 같은 repository 합집합 검색, 업무 요약·branch·핸들 | P05 | A24-01·02·03·07의 로컬 경로, 비공개 후보 누출 반례 |
| 출처 보존, 정상 N:N, 선택 밖 범위 확대 방지 | P09 | 가짜 ACK/사용자 지시, 부모 계보, 다른 후보 권한 반례 |
| 인증된 원격 후보·repository 매핑·선택·왕복 | P11, P12 | A24-02·03·08의 두 물리 머신 증거; D12 요구사항 확정, 원격 구현·실측 별도 |
| 전체 여정과 기존 통신 호환 | P13 | A24-01–08와 기존 62개를 같은 통합 revision에서 대조 |

B03 완료는 P03·P05의 로컬 구현과 해당 게이트 검증이다. 맥북↔맥미니 여정 완료를 뜻하지 않는다. P02의 기존 폴더 연결 보강만으로 세션 단위 협업 목표를 충족했다고 판정하지 않는다. 이미 통과한 G00·G01 이력은 유지하고 새 계약의 소비 경로를 다시 검증한다.

## 5. 확정한 것과 이번에 결정하지 않은 것

- D04의 기본 사용자 흐름과 연결 단위: 명시 공개/같은 repository에서 발견하고, 선택한 세션과 협업한다. 기존 광역 허용의 명시적 사용은 유지한다.
- D06의 발견 공개 경계: 명시 공개 또는 같은 repository이며 업무 확인용 요약을 제공한다. 전체 경로·원문을 추가 공개하는 정책은 채택하지 않았다.
- D02의 제품 의미: 실제 답·대기·취소·후속 회수를 구분한다. 사용자는 `ask`·`reply/status`라는 API 철자나 “짧은” 기본 대기 숫자를 승인하지 않았다. CLI/MCP 이름과 타임아웃 수치는 구현 계약에서 별도로 정하며 이 사용자 결정을 다시 묻는 이유로 삼지 않는다.
- D01의 사용자 출처·중복 적용 방지, D03의 저장 형식, D05의 보존·정리, D07–D11의 첨부·알림·worker·오용·설치 항목은 각 결정 기록을 따른다. D12 제품 요구사항은 ADR-0021로 확정됐고 구체 라이브러리·버전·relay 주소 등 구현 항목은 후속 명세에서 정한다. 미결값을 임의로 승인 처리하지 않는다.

## 6. 실행과 완료 판정

기존 배치·의존성과 게이트당 검토 비용 절감 정책을 유지한다. G02 미완 증거를 G13으로 옮겨 선행 게이트를 통과시키지 않는다. 실제 하네스의 오래된 설치본, 작업 트리 fixture, 새 설치본의 실행 결과를 각각 구분한다. 설계 확정은 G02/G03/G05 또는 원격 구현 완료 증거가 아니다.
