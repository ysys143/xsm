# 설치 CLI 배포물의 정적 분석과 격리 실행

조사일: 2026-10-24. Reason CLI 0.2.557의 macOS arm64 Mach-O 배포물을 읽었다. 바이너리 SHA-256은 `00a94cc9c119a3ab40e7d8454cbf896f99f4cc59e53df721c3de8b8ab98dd7c9`다. 설치 원본을 수정하거나 실제 워커를 새로 실행하지 않았다.

공개 CLI 저장소는 없지만 바이너리에 포함된 Bun JavaScript 중 다음 여섯 모듈은 텍스트로 읽을 수 있었다. NUL 경계와 바이트 오프셋으로 추출해 사설 조사 경로에서 읽었다. 모듈 원문은 저장소에 복제하지 않았고 xsm 코드로 가져오지 않았다. 공개 엔진의 오픈소스 라이선스가 비공개 CLI에 자동 적용된다고 해석하지 않는다.

| 모듈·경로 | 정적 배포물에서 확인한 것 | 반영 |
|---|---|---|
| entry-runtime 설치 | 엔진 버전과 아카이브 SHA를 CLI에 pin. 설치 영수증·파일 fingerprint 재사용. 더 새로운 standalone 설치를 무조건 내리지 않음 | R33·R37·R41. fingerprint는 편의 캐시이며 매 호출 암호학적 무결성 증명과 구분 |

인증 상태 파일·토큰·실제 초대는 읽지 않았다. 여기서 확인한 것은 바이너리 안의 정적 프로그램 텍스트와 데이터 경계이며, 계정 서버를 호출하거나 동작시킨 결과가 아니다. 가입 중단·finisher 경쟁·네트워크 전환·호스팅 relay 장애는 구현 수용 검사에 남긴다.

## 검증 범위

후속 [Ghidra 분석](ghidra-native.md)에서 아래 여섯 모듈의 파일 오프셋을 Mach-O __BUN 세그먼트와 대조하고, Ghidra의 __bun 메모리에서 읽은 바이트 SHA도 모두 일치함을 확인했다. 각 시작 주소는 native 함수가 아닌 비실행 자료 영역이다. native 진입점과 직접 호출 대상의 선택 의사코드도 별도로 확보했다. 초기 전체 자동 분석은 600초에 중단됐고, 후속 시간 제한 없는 기본 자동 분석·전체 함수 목록 추출·저장은 두 대상 모두 완료했다. JS 함수의 의미를 native 의사코드로 복원했다고 해석하지 않는다.

정적 배포물 분석과 기존 실제 실행 기록이 부합하는 지점까지 확인했다. 후속 시험에서는 원본 ask-worker·device-sign-in 모듈의 내부 분기를 격리 실행하고 중단·재시작·HTTP 응답·파일 교체를 주입했다. 실제 자식 모델·전송·계정 서버는 대체했으므로 CLI 전체 통합 시험과 구분한다. 서버의 로그인·계정 증명 발급·호스팅 MCP 구현과 내장 모듈 전체는 이 여섯 모듈만으로 설명할 수 없다.

설치된 CLI의 `network --version`은 엔진 버전을 출력하지 않고 현재 팀 목록을 반환했다. 버전 확인은 CLI 자체 `--version`과 엔진 바이너리 자체 `--version`으로 각각 수행했다. 개인 팀 목록 원문은 공개 근거에 넣지 않았다.

재현은 동일 SHA 바이너리에서 위 바이트 구간을 읽어 수행할 수 있다. 바이너리가 다르면 오프셋을 재사용하지 말고 모듈 경계와 SHA를 다시 확인해야 한다. [추출 메타데이터](cli-extraction.json), [이전 후속 질문 관찰](../../../deliverables/adversarial-cross-review-2026-10-23/reason-workflow-facts.json).

## 후속 구현 추출과 장애 관측

인증의 실제 구현은 바이트 61711343–61725526의 14,183바이트 모듈이다. SHA는 `59a1b3882f8f949ca54291cd61a99b34833a97d8f6e28a0e92368f77738d835c`다. ReasonApi의 실제 구현은 61684095에서 시작한다. [추가 추출 메타데이터](cli-additional-extraction.json)에 두 모듈의 해시·구간·문법 검사를 기록했다. facade의 재수출만 보고 전체 구현을 확인했다고 판정하지 않았다.

바이너리 전체의 `// @bun` 마커와 NUL 경계 후보는 129개이며, Node의 module 문법 검사를 통과한 후보는 125개다. 나머지에는 Bun 내부 문자열·CSS·추출 경계 또는 런타임 차이가 개입하므로 유효 JS 모듈 수로 단정하지 않는다. [전체 후보 목록](cli-module-manifest.json). 129개를 모두 의미 분석했다고 주장하지 않으며, 네트워크 기능의 호출 경로는 위 8개 구현과 공개 엔진·실제 동작을 대조했다.

[후속 실행 보고](followup-findings.md)는 원본 모듈 실행 15개 워커 관측과 12개 인증 관측을 설명한다. 요청·답 저널의 복구와 발신자별 문맥 재사용을 확인한 동시에, 가득 찬 풀의 새 워커 즉시 회수, 결과 저장 전 중단의 부작용 중복, pending flow 교체 뒤 이전 인증 결과 저장의 조건부 틈을 기록했다. 원본 모듈과 실제 모델 전체의 검증 범위를 분리한다.
