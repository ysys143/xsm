# 스파이크 S12 설계: 싼 모델이 보드 변경을 걸러 읽을 수 있는가

- 상태: 설계. 미실행
- 작성일: 2026-10-30
- 관련: [S11 마크다운 보드](S11-markdown-board-plan.md), [채널 설계 토론](../plan/collaboration/channel-design-discussion.md), ADR-0012
- 목적: 보드가 바뀌었다는 짧은 알림을 받은 세션이, 싼 모델 서브에이전트로 변경을 걸러 자기 일과 관련 있는 것만 받는 방식이 쓸 만한지 확인한다. 가장 큰 위험은 관련 있는 변경을 "관련 없음"으로 조용히 거르는 것이므로, 재현율을 먼저 본다.

## 1. 확인할 질문

| ID | 질문 |
|---|---|
| Q1 | 싼 모델 필터가 관련 있는 변경을 얼마나 넘기는가(재현율). 특히 이름이 직접 나오지 않는 미묘한 경우 |
| Q2 | 필터가 바꿔 말하지 않고 원문 인용으로 돌려주는가 |
| Q3 | 모델 없이 기계적으로 거르는 것만으로 어디까지 되는가 |
| Q4 | 호출 한 번의 토큰과 시간 |

## 2. 시험 자료 (실행 전에 고정)

- 합성 보드 `BOARD.md` 한 개: `##` 항목 약 30개(결정, 담당, 진행, 자원).
- 합성 세션 4개: 각자 짧은 작업 설명을 가진다(맡은 항목, 다루는 파일, 작업이 기대는 전제 한두 개).
- 변경 묶음 10개: 묶음마다 보드 항목 8개가 바뀐 diff. 각 세션에 대해 변경마다 정답 라벨을 단다.

| 라벨 | 뜻 | 예 |
|---|---|---|
| R1 직접 | 그 세션이나 그 세션의 담당 항목을 지명 | "담당: B — 리뷰어로 C 추가" |
| R2 겹침 | 다른 세션이 같은 일을 시작했지만 B를 지명하지 않음 | B가 캐시 계층을 고치는 중인데 D가 "캐시 무효화 리팩터 착수" |
| R3 전제 | B의 작업이 기대는 전제를 뒤집는 결정 | B는 Redis를 전제하는데 "결정: Redis 폐기, 메모리 캐시로" |
| R4 자원 | B가 필요한 자원을 다른 세션이 점유 | "자원: GPU VM 1대 D가 18시까지 사용" |
| N 무관 | B의 일과 관련 없음 | |

- 라벨은 계획 작성자가 실행 전에 단다. 작성자 편향을 줄이려고 다른 세션 하나가 라벨을 따로 달고, 서로 다른 라벨은 실행 전에 합의하거나 "모호"로 표시해 집계에서 따로 센다.
- 사례 수: 세션 4개 × 묶음 10개 = 40사례(변경 판정 320건).

## 3. 비교 조건

| ID | 필터 | 비고 |
|---|---|---|
| F0 | 기계적: 세션 이름·담당 항목·다루는 파일 경로의 문자열 일치 | 모델 없음. R1·R4의 기준선 |
| F1 | haiku 서브에이전트 | `claude -p --model haiku` |
| F2 | luna 서브에이전트 | `codex exec`, `openai/gpt-6-luna`(ocx). 실제 응답 모델을 로그로 확인 |
| F3 | 메인 세션 급 모델 | 상한 참고용. 묶음 3개만 |

- F1·F2·F3은 같은 프롬프트를 쓴다. 입력은 그 세션의 작업 설명과 변경 diff다. 출력 형식은 고정한다: 관련 항목마다 `항목 제목`, `보드 원문 인용`, `이유 한 줄`. 요약이나 바꿔 말하기는 금지한다.
- 반복: 전체 40사례를 조건마다 1회 돈다. 분산을 보려고 10사례는 F1·F2로 3회씩 더 돈다.
- 구독 경로만 쓰고 API 키 과금 경로는 쓰지 않는다. 이 실험은 모델의 판단을 보는 것이라 일회성 실행으로 충분하다(xsm 세션 거동을 재는 실험이 아니다).

## 4. 셀 것과 판정

- 재현율: 라벨별(R1–R4)로 따로. R2·R3을 가장 중요하게 본다.
- 정밀도: 무관(N)을 관련으로 넘긴 비율.
- 인용 충실도: 돌려준 인용이 보드 원문과 글자 그대로 일치하는 비율.
- 호출당 입력·출력 토큰과 시간.
- 판정(제안값, 사용자가 정한 값이 아님):
  - F1 또는 F2가 R2·R3 재현율 90% 이상, 인용 충실도 95% 이상이면 그 모델의 걸러 읽기를 스킬에 권장할 근거로 본다.
  - F0이 R1·R4를 대부분 잡고 모델 필터들이 R2·R3에서 기준에 못 미치면, 미묘한 경우는 걸러 읽기에 맡기지 않는다. 그런 변경은 쓰는 쪽이 관련 세션에 DM으로 알리는 관행이 필요하다는 근거로 본다.
  - 반복 사이의 재현율 차이가 10%p를 넘으면 결론을 내지 않고 사례를 늘려 다시 돈다.

## 5. 이 실험이 말해 주지 않는 것

- 합성 작업 설명은 실제 세션이 가진 맥락보다 훨씬 짧다. 실제 세션의 맥락을 필터에 얼마나 넘길 수 있는지는 재지 않는다.
- 필터 결과를 받은 메인 세션이 실제로 그에 따라 행동하는지는 재지 않는다.
- 알림을 모아 보내는 방식, 실제 보드 크기와 변경 빈도에서의 누적 비용은 재지 않는다.
- 라벨은 사람(또는 세션)의 판단이라, 정답 자체에 틀린 것이 섞일 수 있다.
