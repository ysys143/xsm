## 제안 기준과 해석

**R2·R3 재현율 90%, 인용 충실도 95%, 반복 차이 10%p는 계획 작성자의 제안값이며 사용자가 정한 값이 아니다.** 라벨별·전체 반복 차이 중 어느 것이든 10%p를 넘으면 계획에 따라 해당 모델에 대한 권장 결론을 보류한다.

- F1: 이 표본에서는 제안 기준을 충족했다. R2 100.0%, R3 100.0%, 인용 100.0%, 반복 안정 조건 True.
- F2: 이 표본에서는 제안 기준을 충족했다. R2 100.0%, R3 95.5%, 인용 98.8%, 반복 안정 조건 True.

이 자료는 작업 영역이 네 개로 뚜렷하고 대부분의 관련 변경을 영역당 두 개씩 배치한 합성 표본이다. 은어·대명사·간접 일정 의존·정반대 의미의 무관 문장 같은 어려운 음성 사례는 충분히 포함하지 않았다. 라벨러 둘은 독립 실행했지만 하나는 자료를 만든 세션, 다른 하나는 모델이라 사람 정답을 대신하지 않는다. 따라서 실제 장기 세션에서 조용한 누락이 안전한지까지 보증할 수 없다.

Q1은 위 라벨별 재현율과 반복 차이, Q2는 인용 일치율, Q3는 F0 비교, Q4는 호출별 토큰·시간으로 답했다. 필터 결과를 받은 메인 세션의 행동, 실제 세션 문맥 전달량, 대형 보드·실제 변경 빈도의 누적 비용은 측정 범위 밖이다.

## 집계 검증과 재현

`verify_artifacts.py`가 고정 해시, 고정 전후 시각, 프롬프트 일치, 계획 호출 수 70·70·12, 라벨 320건, 실제 응답 모델과 대응 프록시 로그를 검증했다. 결과는 `artifact-verification.json`의 `verified=True`다. CLI와 프록시 토큰 집계 불일치는 0건이었다.

저장된 자료만으로 아래 명령을 실행하면 모델 호출 없이 재집계와 보고서 생성이 가능하다.

```sh
python3 deliverables/s12-board-filter/verify_metrics.py
python3 deliverables/s12-board-filter/verify_artifacts.py
python3 deliverables/s12-board-filter/write_report.py
```

`verify_metrics.py`는 R2 누락, 원문 인용 변조, 무관 항목 삽입, 알 수 없는 ID, 중복 ID를 일부러 주입하고 각 지표가 이를 탐지하는지 검사한다. 결과는 `metrics-verification.txt`에 있다. `build_fixture.py`는 자료의 생성 원본이며, 실행하면 고정 시각을 다시 쓰므로 보존된 고정 자료에 덮어 실행하지 않는다.

기존 저장소 코드·문서는 수정하지 않았으며 결과 문서 하나와 지정한 원시 자료 디렉터리에만 산출물을 추가했다. 커밋·push는 하지 않았다.
