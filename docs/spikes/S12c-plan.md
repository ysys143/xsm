# 스파이크 S12c 설계: 더 크고 긴 표본에서 사용자 기준으로 걸러 읽기를 판정한다

- 상태: 설계. 모든 모델 호출(독립 라벨 포함) 전에 작성
- 작성일: 2026-10-30
- 관련: [S12 설계](S12-board-filter-plan.md), [S12 결과](S12-results.md), [S12b 설계](S12b-hard-sample-plan.md), [S12b 결과](S12b-results.md)
- 자료·스크립트: [deliverables/s12c-board-filter](../../deliverables/s12c-board-filter/)

## 1. 왜 S12c인가

S12b는 어려운 표본에서 haiku(F1)와 luna(F2)를 쟀다. 그러나 결과 문서의 "이 실험이 말해 주지 않는 것"에 네 가지 빈틈이 남았다. 항목이 65–79어절로 짧았다. 반복 사례 10개에 R2 셀이 하나도 없어 R2 반복 차이를 재지 못했다(사례를 고를 때 라벨 분포를 보지 않은 설계 실수). 라벨별 분모가 작아 한 건으로 수십 %p가 움직였다. 기준값은 계획 작성자의 제안값이었다.

S12c는 질문, 라벨 체계, 필터 프롬프트, F0–F3 조건을 S12b에서 그대로 가져오고, 사용자가 고른 네 가지만 바꾼다. 코드는 `deliverables/s12b-hard-sample/`을 복사해 고쳤고 원본은 건드리지 않는다.

| 바꾼 것 (사용자 선택) | S12b | S12c |
|---|---|---|
| 1. 긴 항목 | 65–79어절 | 항목 104개 중 52개가 150–200어절, 나머지 52개는 60–100어절 |
| 2. 층화 반복 | 묶음마다 세션을 돌려 고른 10사례, R2 0셀 | 라벨 분포를 보고 고른 26사례, 작성자 라벨로 R1 10, R2 12, R3 16, R4 16셀 |
| 3. 표본 두 배 | 세션 5, 묶음 10, 400셀, R2 15·R3 22·R4 14 | 세션 7, 묶음 13, 728셀, 작성자 라벨 R2 39·R3 37·R4 44. 최종 라벨에서 각각 30셀 이상이어야 진행 |
| 4. 전체 읽기 기준선 | 없음 | F4: 메인 급 모델이 필터 지시 없이 묶음 전체를 읽는 호출과, 필터 결과만 읽는 호출의 토큰·시간 |

S12b의 어려운 표본 성질은 유지한다. 세션 설명에 전제·자원 목록이 없다. R2·R3·R4 항목은 그 세션의 구별 단어를 하나도 쓰지 않는다(기계 검사). 같은 단어를 쓰지만 무관한 어려운 음성 셀이 있다. 세션들의 영역이 겹친다.

## 2. 사용자 기준 (2026-10-30 사용자 결정)

아래 기준은 **사용자가 2026-10-30에 정한 것이다.** 계획 작성자의 제안값이 아니다. 필터 호출 전에 `policy.json`의 `criteria`에 고정한다.

| 기준 | 값 | 계산 |
|---|---|---|
| 재현율 | R2, R3, R4 **각각** 95% 이상 | 기본 실행(조건의 전체 사례)에서 라벨별 TP/정답 셀 |
| 정밀도 | 70% 이상 | 기본 실행에서 TP/(TP+FP). 모호 셀은 빼고 따로 센다 |
| 반복 차이 | 10%p 이하, **전체와 R1·R2·R3·R4 각각** | 반복 26사례의 4회(기본 실행 + 추가 3회) 재현율 최댓값−최솟값. 분모가 0인 라벨은 NA이며 NA는 미충족으로 본다 |
| 인용 충실도 | 95% 이상 | 기본 실행의 반환 항목 가운데, 인용이 같은 ID 항목의 변경 후 본문에 들어 있는 비어 있지 않은 연속 문자열인 비율 |

- 인용 충실도 정의: S12b의 F2·F3가 항목 본문 전체를 인용했으므로, **본문 전체를 그대로 복사한 인용도 원문 그대로(충실)로 센다.** 대신 충실 인용을 "본문 전체"(앞뒤 공백을 뺀 인용 = 앞뒤 공백을 뺀 본문)와 "발췌"로 나눠 비율을 따로 보고한다. 다른 항목에서 가져온 인용, 알 수 없는 ID의 인용은 불충실이다.
- **한 모델은 네 기준이 모두 성립할 때만 기준을 충족한다.** 하나라도 못 미치면 미충족이다.
- 판정 대상은 F1(haiku)과 F2(luna)다. F3(sol)는 반복을 돌리지 않아 반복 차이가 없으므로 "판정 불가"로 적는다. F4는 걸러 읽기 조건이 아니라 비용 비교 기준선이라 판정하지 않는다.
- 결과 문서는 이 기준을 숫자 그대로 기계적으로 적용한 충족/미충족만 적는다. 그 너머의 권고는 쓰지 않는다.

## 3. 시험 자료 (필터 호출 전에 고정)

- 세션 7개. S12b의 5개(Heron, Kestrel, Wren, Plover, Tern)는 작업 설명을 그대로 쓰고, 두 개를 더했다.
  - Avocet: 주문서로 넘어가기 직전의 장바구니 가격·재고 재검증(`#44`, `svc/cart/revalidate.go`).
  - Godwit: 출판사별 월간 정산 보고서 야간 배치(`#51`, `jobs/settlement/monthly_report.py`).
  - 더한 이유: 셀 수를 두 배로 늘리려면 한 항목이 둘 이상의 세션에 걸리는 공유 전제·자원이 필요하다. Godwit은 Kestrel(jobq, Postfly), Wren(일 단위 매출 집계, 웨어하우스 질의 슬롯), Tern(구매 데이터 스냅숏 복제본)과, Avocet은 Tern(loadbox-2)과 겹친다.
- 세션 설명은 이름, 작업 두 문장, 담당 항목 번호 하나, 파일 하나뿐이다. 숨은 전제·자원 메모(`src/sessions.json`의 `hidden_author_notes`)는 필터와 독립 라벨러 어느 쪽에도 주지 않는다. S12b에서 모호로 뺀 "Tern의 캐싱 위치"는 이번에도 Tern 관련으로 삼지 않는다.
- 변경 묶음 13개, 묶음마다 항목 8개, 같은 초기 보드에 대한 독립 diff다. 사례 91개(7세션 × 13묶음), 판정 셀 728개.
- 항목 길이: 묶음마다 긴 항목 4개(150–200어절), 짧은 항목 4개(60–100어절). 어절은 공백 단위다.
- 작성: B01–B05는 이 세션이, B06–B13은 이 세션에서 갈라진 하위 에이전트 둘이 같은 규칙과 배정표로 썼다. 모두 같은 검사기를 통과해야 한다. 작성자는 셋이지만 같은 계획과 같은 숨은 메모를 공유하므로 독립 작성자로 보지 않는다.
- 작성자 라벨: R1 15, R2 39, R3 37, R4 44, N 593셀. 어려운 음성 표시 32셀.
- 고정 전 기계 검사(`build_fixture.py`, 하나라도 어기면 고정하지 않는다):
  1. 항목 본문이 60–100어절 또는 150–200어절이고, 긴 항목이 전체의 45–55%다.
  2. 세션 S에 대해 R2·R3·R4인 항목의 제목·본문에 S의 구별 단어가 하나도 없다(대소문자 무시, 부분 문자열).
  3. S의 어려운 음성으로 표시한 항목은 S의 구별 단어를 하나 이상 포함하고 S에 대해 N이다.
  4. R1 항목에는 세션 이름·담당 항목 번호·파일 경로 가운데 하나가 글자 그대로 있다.
  5. 세션 설명에 전제·자원 목록 필드가 없다.
  6. 작성자 라벨 R2·R3·R4가 각각 36셀 이상이다(최종 30셀 요구에 대한 여유).

## 4. 라벨

라벨 다섯 개, 정의, 우선순위(R4 > R3 > R2 > R1)는 S12b와 같다. 독립 라벨 프롬프트도 S12b의 문장을 그대로 쓴다.

- 작성자 라벨을 고정한 뒤, 별도 `claude -p --model opus` 실행(도구 없음, MCP 없음)이 작성자 라벨과 숨은 메모 없이 세션 설명·변경·라벨 규칙만 받아 독립 라벨을 단다. 관련 셀만 열거하고 생략 셀은 N으로 본다.
- 두 라벨이 다른 셀은 필터 호출 전에 하나씩 본다. 작성자가 고칠 근거가 있으면 근거를 적고 고친다. 근거가 갈리면 모호로 고정하고 주요 지표에서 빼서 따로 센다. 처리는 `reconcile.py`에 적고 해시로 고정한다.
- 최종 라벨에서 R2·R3·R4가 각각 30셀 미만이면 필터를 호출하지 않고 멈춘 뒤 보고한다. 항목을 더해 다시 라벨링하지 않는다.
- 결과를 본 뒤 라벨이나 기준은 바꾸지 않는다.

- F4는 메인 세션이 보드를 직접 읽는 경우의 비용 기준선이다. 프롬프트에는 "당신의 작업과 관련 있는 것이 무엇인지 답하라"와 출력 형식(JSON, ID와 이유)만 있고, 직접 지명·겹침·전제·자원 같은 필터 지시는 없다. 출력 형식은 고른 항목을 집계하려고 둔다. F4에는 네 갈래가 있다.
  - F4a: 묶음 diff 전체를 읽는다(21사례).
  - F4b: 같은 사례에서 F1 기본 실행이 돌려준 항목(ID, 제목, 인용, 이유)만 읽는다(21사례). 앞에 "필터가 골라 준 것만 담고 있다"는 한 줄을 붙인다.
  - F4c: 같은 방식으로 F2 기본 실행의 결과를 읽는다(21사례).
  - F4z: 변경 없이 세션 설명만 준다. 실행 환경의 고정 부담을 재는 보정 호출(Heron·Wren·Godwit, 3회).
- 계획 호출 수: 독립 라벨 1회 + F1 169 + F2 169 + F3 21 + F4 66 = **모델 호출 425회**(라벨 제외). F0는 로컬 91사례.
- 실행 순서: 1단계에서 F1과 F2를 두 갈래로 동시에 돌린다(갈래 안에서는 순차). 각 갈래의 첫 호출에서 실제 응답 모델을 확인한 뒤 나머지를 돈다. 2단계에서 한 갈래로 F3, F4z, F4a, F4b, F4c를 차례로 돈다. F4의 시간을 다른 호출과 겹치지 않게 재려고 2단계를 따로 둔다.
- 실제 응답 모델 확인: F1은 CLI 결과의 `modelUsage` 키, F2·F3·F4는 ocx 기록의 `requestedModel`·`servedModel`과 시도별 `model`(대화 ID = `sha256(thread_id)[:32]`)이다. 매 호출 확인한다. 확인하지 못하거나 다른 모델이면 남은 호출을 모두 멈춘다. 대체 모델이나 다른 과금 경로로 바꾸지 않는다.

## 6. F4 비용 비교의 정의

F3·F4 21사례마다 두 경로를 나란히 놓는다.

- 전체 읽기 경로: F4a 한 번.
- 걸러 읽기 경로: 싼 모델 필터 한 번(그 사례의 F1 또는 F2 기본 실행 호출) + 메인 급 모델이 필터 결과를 읽는 한 번(F4b 또는 F4c).

보고하는 값:

1. 호출당 원시값: 입력 토큰(캐시 포함 총 입력), 캐시 입력, 출력 토큰, 프로세스 시간. 조건별 평균·중앙값과 사례별 값.
2. 메인 급 모델의 한계 입력 토큰: 각 F4a·F4b·F4c 호출의 입력 토큰 − F4z 3회 평균 입력 토큰. CLI의 시스템 지시처럼 실제 메인 세션에서는 이미 치른 고정 부담을 빼고, 보드 내용 때문에 메인 세션 맥락에 더해지는 양을 보려는 것이다.
3. 비교 표: 사례마다 (a) 메인 급 한계 입력 F4a 대 F4b·F4c, (b) 메인 급 출력 토큰, (c) 걸러 읽기 경로에 더해지는 싼 모델 토큰, (d) 순차 시간 F4a 초 대 (F1 초 + F4b 초), (F2 초 + F4c 초). 모델이 다른 토큰은 돈으로 바꾸지 않고 나란히 적는다.
4. 참고값: F4a·F4b·F4c가 고른 항목의 라벨별 재현율과 정밀도. 사용자 기준의 판정에는 쓰지 않는다.

F1·F2 호출 시간은 1단계의 두 갈래 동시 실행 중에 쟀고, F4는 2단계에서 혼자 쟀다는 차이를 결과에 적는다.

## 7. 셀 것

- 라벨별(R1–R4) 재현율, 전체 관련 재현율.
- 정밀도 TP/(TP+FP), N 통과율 FP_N/N, 어려운 음성 통과율, 단어 겹침 N 통과율. 모호 셀 선택 수.
- 인용 충실도와 그 안의 본문 전체/발췌 비율, 충실 인용의 본문 대비 길이. 긴 항목과 짧은 항목을 나눈 재현율과 인용 분포.
- 반복 26사례의 회차별 재현율과 전체·라벨별 차이.
- 호출당 토큰과 시간, F4 비용 비교.
- 계획 대비 실행 호출 수, 모든 오류와 이상치.
- 마지막 절: 사용자 기준을 F1·F2에 기계적으로 적용한 충족/미충족과 각 수치·기준값.

## 8. 운영 규칙

- 구독 경로만 쓴다. 모든 모델 호출 명령은 `env -u ANTHROPIC_API_KEY -u OPENAI_API_KEY`로 시작하고, 자식 환경에서도 두 변수를 지운다. 키 값과 인증 파일 내용은 읽지도 출력하지도 않는다.
- 계정 식별자를 남기지 않는다. S12b와 같이 원시 표준 출력·표준 오류를 파일로 쓰지 않고, 집계에 필요한 필드만 골라 `scrub()`을 거쳐 저장한다. 끝에 `scrub_check.py`로 산출물과 S12c 문서 전체를 검사하고, 명령과 건수만 보고한다(값은 출력하지 않는다).
- 사용자 설정을 바꾸지 않는다. 첫 Codex 호출 전에 `~/.codex`·`~/.codex-2`·`~/.codex-3`의 `config.toml` SHA-256을 기록하고, 저장소 밖 임시 디렉터리에 백업한다. Codex는 git 저장소 밖 임시 디렉터리에서 `--skip-git-repo-check`로 실행한다. 마지막 호출 뒤 해시를 비교하고, 달라졌으면 백업으로 되돌린 뒤 보고한다. 인증 파일은 복사하지 않는다. ocx 설정은 건드리지 않고 기록만 읽는다.
- 인증·프록시·모델 사용 불가로 막히면 멈추고 보고한다.
- 쓰는 곳은 `docs/spikes/S12c-*`와 `deliverables/s12c-board-filter/`뿐이다. 커밋·push는 하지 않는다.

## 9. 이 실험이 말해 주지 않는 것

- 표본은 여전히 합성 자료다. 작성자 셋이 같은 계획과 숨은 메모를 공유했다. 어렵게 만들려는 의도가 실제 팀 보드의 분포와 같다는 보장은 없다.
- 단어 분리는 고정한 구별 단어 목록 안에서만 성립한다. 목록 밖의 같은 뜻 표현은 단서가 될 수 있다.
- 공유 자원·전제를 늘리려고 Godwit이 여러 세션과 겹치게 만들었다. 한 세션에 관련 셀이 몰려 있으므로 세션별 차이를 일반화하지 않는다.
- 반복은 26사례×4회다. 라벨별 분모가 10–16셀이라 한 건이 6–10%p를 움직인다.
- F3·F4는 effort `low`의 21사례다. 높은 effort의 상한은 재지 않는다.
- F4의 "필터 지시 없음"은 출력 형식 지시까지 없앤 것은 아니다. 실제 메인 세션은 보드 변경을 다른 맥락과 함께 읽으므로, 이 호출의 토큰·시간은 맥락이 없는 단독 호출의 값이다.
- 필터 결과를 받은 세션이 실제로 행동하는지, 실제 보드 크기와 변경 빈도에서의 누적 비용은 재지 않는다.
