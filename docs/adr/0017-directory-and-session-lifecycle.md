# ADR-0017: 업무로 세션을 찾고 대화 신원을 유지한다

- 상태: Proposed
- 관련 목표: G1, G2, G5
- 작성일: 2026-10-24
- 비교 근거: [Reason 비교 노트](../references/reason.md)
- 기존 결정 효력: 이 문서는 아직 Accepted ADR을 대체하지 않는다.

## 질문

업무 맥락으로 협력자를 고르면서도 이름·프로세스·대화·홈·머신의 수명을 혼동하지 않으려면 무엇을 디렉터리와 주소에 담을 것인가?

## 맥락

Reason은 사람·머신·런타임·repo@branch·상태 지속 시간·doing·수신 등급을 보여 주고 제목과 할 일을 자동 추출한다. 네이티브 대화 ID가 있는 주소는 기억 기간 동안 보존하지만, proc 기반 주소와 사람 우편함은 다른 수명을 갖는다. 이 차이는 편의와 비용을 함께 만든다. [directory.rs](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/src/daemon/directory.rs), [doing.rs](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/src/doing.rs), [sessions.rs](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/src/daemon/sessions.rs).

현재 xsm은 [registry](../../xsm/registry.py)·[probe](../../xsm/probe.py)에서 홈과 런타임을 보존하고 [resolve](../../xsm/resolve.py)로 이름을 해석한다. 같은 저장소에서 이름만으로 직접 통신했다. 구조화된 업무·브랜치·수신 능력 표시는 부족하다. Reason에서는 같은 일반 Codex 스레드에 도달하지 못한 반대 표본이 있으므로 주소가 쉬운 것과 바인딩의 정확성을 구별한다.

## 선택지

| 안 | 방식 | 이점 | 비용·위험 |
|---|---|---|---|
| A | 런타임 이름·ref·폴더만 제공 | 메타데이터 수집이 작음 | 담당 업무를 추측하거나 사람에게 재질문 |
| B | 실행 신원과 대화 신원을 보존한 업무 디렉터리 | 목적에 맞는 상대 선택과 재개 판단 가능 | 하네스별 추출·신선도·공유 범위 관리 |
| C | xsm이 전역 이름과 모든 세션 메타데이터를 소유 | 표시 체계 통일 | 사용자의 네이티브 이름과 경합, 상태 유출·강제 편입 위험 |

## 제안 계약

B를 제안한다.

- 주소 표시와 실제 목적지 핸들을 분리한다. 로컬 핸들은 runtime·정규화한 home·native conversation ID를 포함하고, 실행 세대(pid·시작 시각 등)는 전달 가능성 검증에 사용한다. 원격은 인증된 머신 신원을 추가한다. 짧은 ref만으로 권한을 결속하지 않는다.
- 사용자 이름을 덮어쓰지 않고 0008의 모호성 처리를 유지한다. 업무 정보는 후보를 고르는 근거이지 모호한 주소를 조용히 다른 세션으로 바꾸는 권한이 아니다.
- 목록에는 업무·repo/branch·busy/idle·관측 시각·수신 능력·현재 호출자 표시를 제공한다. 지원하지 않는 값은 unknown이다. busy만으로 요청을 거부하지 않는다.
- 업무 설명은 런타임이 이미 기록한 제목·진행 중 할 일에서 필요한 요약만 추출한다. 추가 LLM 호출이나 수동 보고를 필수로 하지 않는다. 캐시에는 출처·관측 시각을 남기고 잘린 줄·대화 전환·파일 재작성에 대응한다.
- 공유 MCP의 매 호출 신원을 먼저 해석한다. 환경 변수는 다른 에이전트에서 상속될 수 있으므로 단독 근거로 사용하지 않는다. 자료 루트와 승인 주체도 같은 신원을 사용한다.
- 대화 재개, 같은 프로세스의 새 대화, 새 프로세스의 같은 대화, 다른 머신의 동명 세션을 구별한다. 원래 대화용 미독을 새 대화에 자동 상속하는 정책은 별도로 결정한다.
- 전체 경로와 doing 공개 범위를 사용자가 확인할 수 있게 한다. 폴더 제외는 디렉터리뿐 아니라 등록·훅·첨부에 일관되게 적용하고 심볼릭 링크와 아직 없는 하위 폴더를 검사한다.
- 사람의 터미널은 머신별 회신 주소를 보존한다. 사람이 계정 이름으로 인증됐다는 사실로 에이전트가 수행할 업무 권한을 추론하지 않는다.

## 기존 결정과 이행

0001의 포인터·발견 예산, 0008의 네이티브 이름·주소 문법은 호환해야 한다. 기존 ref를 바꾸지 않고 추가 필드부터 도입할 수 있다. 이름 재사용·오프라인 주소·자동 메타데이터 공유 정책이 달라지면 해당 ADR의 사용자 결정이 필요하다. 현재 MCP 호출자 대체 정책에는 사용자의 접근성 우선 판단이 들어 있으므로, caller ID 누락을 이유로 모든 통신을 막는 변경을 자동 채택하지 않는다. 잘못된 이웃을 승인 주체나 첨부 루트로 쓰는 문제는 별도로 방지한다.

## 수용 검사

- A17-01: 여러 홈·런타임의 동명 세션에서 업무·branch로 후보를 찾고, 최종 대상은 실제 핸들과 일치한다.
- A17-02: 공유 MCP 하나에서 서로 다른 두 대화·폴더를 번갈아 호출해 발신자·자료 루트·권한이 섞이지 않는다.
- A17-03: resume·새 대화·이름 변경·pid 재사용·다른 머신의 동명을 각각 검사한다.
- A17-04: 작업 상태 추출기가 없는 하네스도 기본 통신을 수행한다. 제목·계획 갱신·부분 기록·캐시 만료를 검사한다.
- A17-05: 제외 폴더의 문자열 경로와 실제 경로가 달라도 등록·목록·첨부 정책이 일치한다.
- A17-06: 과거 대화가 오프라인인 상태에서 동명 새 세션으로 미독이나 승인 권한이 넘어가지 않는지 선택한 수명 계약으로 검증한다.

## 비용과 되돌리기

네이티브 저장 형식 변경을 계속 추적해야 하고 업무 정보가 민감할 수 있다. 표시·검색 기능과 전달 기능의 장애를 분리한다. 추가 메타데이터 추출을 끄고 기존 목록으로 돌아갈 수 있어야 하며 기존 주소와 미독 이력은 유지한다.

## 미결 매개변수

doing·전체 경로의 공유 기본값, 상태 신선도 예산, 대화 이름 보존 기간, proc 기반 주소의 상속 의미, 호출자 신원 미확정 시 허용할 동작 범위를 논의해야 한다.
