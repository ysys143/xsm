# ADR-0024: 공개된 후보를 찾고 선택한 세션과 협업한다

- 상태: Accepted
- 결정일: 2026-10-28
- 결정자: 사용자
- 관련 목표: G1, G2, G4, G5
- 관련 제안: ADR-0015, 0016, 0017, 0020, 0021, 0022
- 적용 범위: 발견 대상·공개·선택·협업 연결의 제품 계약. 구현 완료 판정과 별개다.

## 맥락

사용자는 다음 흐름을 지정했다.

> macmini에서 이 작업 하고 있는 세션 찾아와봐.

에이전트가 a1, a2, b1, b3의 작업 정보를 보여주고, 사용자가 확인한 뒤 “a1이랑 붙어서 일하자”라고 하면 에이전트가 핸드셰이크를 진행하고 함께 작업한다. 후보는 사전에 “이 세션들은 xsm에서 찾을 수 있게 공개해놔”라고 지시한 세션들과 같은 repository의 폴더·워크트리에 속한 세션들이다.

기존 ADR-0004의 같은 저장소 자동 통신은 유지한다. 다른 저장소의 특정 세션을 선택했을 때 폴더 전체를 연결하는 기본 동작은 이 사용자 의도를 표현하지 못한다. ADR-0009는 폐기된 pair/HMAC 신뢰 체계의 이력이며 여기서 복원하지 않는다.

## 결정

발견 후보는 **사용자가 명시적으로 공개한 세션 ∪ 같은 repository의 폴더·워크트리 세션**으로 정하고, 사용자가 선택한 실제 세션과 핸드셰이크한 뒤 협업한다.

1. 머신·작업·repository·branch로 이 후보 집합을 검색한다. 명시 공개 집합은 다른 폴더·repository·허용된 다른 머신의 세션도 포함한다. 같은 repository 집합에는 별도의 공개 명령을 요구하지 않는다. 등록·머신 인증·제외/차단 정책은 유지한다.
2. 공개는 후보 표시와 작업 확인을 위한 허용이다. 전역 인터넷 공개, 새 머신 가입, 자동 협업·업무 위임·파일 접근 허용으로 해석하지 않는다. 사전 공개 지시의 주체와 적용 세션을 보존한다.
3. 후보에는 머신, 네이티브 이름, repository/branch, 확인 가능한 작업 요약, 상태, 관측 시각과 출처를 제공한다. 미지원·오래된 값은 unknown/오래됨으로 표시한다. 전체 transcript·절대 경로·자료 원문을 새로 공개하는 기본값은 만들지 않는다.
4. 후보 표시만으로 새로운 협업 관계를 만들거나 상대에게 작업을 보내지 않는다. 사용자가 작업을 확인하고 대상을 선택할 수 있게 한다. 기존 같은 repository의 통신 권한은 계속 유효하다.
5. “a1이랑 붙어서 일하자”는 선택한 세션과 양방향 협업하라는 사용자 지시다. 내부 project·ref·추가 폴더 연결 승인을 다시 요구하지 않는다. 후보가 모호하거나 선택한 대화가 교체된 경우에는 그 사실을 알려 대상을 확인한다.
6. 새 허용은 요청 세션과 선택한 세션의 native conversation 신원에 결속한다. 다른 후보·폴더 전체·repository 전체·파일 권한·모델 실행 권한으로 확대하지 않는다. 기존 link/join/reach의 명시적 명령과 기존 승인 기록은 보존한다.
7. 핸드셰이크는 선택한 상대의 신원·수신 가능성·회신 경로·협업 의도 확인이다. 머신 인증과 사용자 승인을 별도로 검사한다. 상대 에이전트의 ACK는 사람의 승인이 아니다. 추가 사람 승인이나 로컬 pair/HMAC을 모든 기존 메시지의 선행 조건으로 넣지 않는다.
8. 실제 상대의 상관된 응답을 받아야 “핸드셰이크 완료”라고 말한다. 소켓 write·큐 접수·전달 영수증만으로 완료하지 않는다. busy/timeout/offline은 대기·복구 가능한 상태로 표시하고 같은 요청 ID로 후속 답을 회수한다.
9. 부모·자식·형제 관계는 검색·연결 자격이 아니다. 로컬과 원격에 같은 사용자 흐름을 제공한다. 원격 신뢰와 전송 수단은 ADR-0007 및 P11/D12/P12에서 별도로 검증·선택한다.
10. 공개 철회는 후속 발견에, 협업 해제·세션 종료·권한 철회는 후속 연결/전송에 반영한다. 새 대화·동명 세션으로 승인과 미독을 넘기지 않는다. 같은 대화의 resume은 신원·권한 재확인 후 재접속하며 같은 유효 승인을 반복해 묻지 않는다. 임의 숫자 TTL로 이 계약을 대체하지 않는다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 모든 등록 세션을 기본 공개 | 사전 공개 또는 같은 repository라는 후보 경계를 넘는다 |
| 세션마다 공개 명령 필수 | 같은 repository·워크트리 후보까지 매번 편입시켜야 한다 |
| 공개와 동시에 자동 협업 | 사용자가 후보의 작업을 확인하고 선택하는 단계를 없앤다 |
| 상대 하나를 고르면 폴더 전체 link/join | 선택하지 않은 동료에게도 새 권한이 열린다 |
| 모든 전송 전에 별도 사람 승인·pair 신뢰 수립 | 명시적 선택과 기존 repository 허용을 중복 확인하며 폐기된 ADR-0009를 복원한다 |

## 결과와 비용

디렉터리 공개와 통신 권한을 분리해 저장·철회해야 한다. 세션 단위 협업 관계와 핸드셰이크 요청·응답의 상관관계, 재개 시 신원 확인이 필요하다. 작업 요약 추출 실패가 기본 통신을 막아서는 안 된다. 로컬만 성공한 검사는 원격 사용자 여정의 완료 증거가 아니다.

## 기존 ADR과의 관계

ADR-0004의 같은 repository 자동 범위와 명시적 link/join/reach를 보존하고, 특정 세션 선택에 대한 협업 관계를 추가한다. 0015·0017의 관련 미결은 이 결정이 우선하며 해당 문서 전체가 Accepted가 된 것은 아니다. 0016의 공개 API 철자·대기 시간 숫자, 원격 backend, 첨부/보존/worker 정책은 이번 결정에 포함되지 않는다. 이 값들을 사용자가 승인한 것처럼 기록하지 않는다.

## 수용 조건

- A24-01: 후보가 명시 공개 집합과 같은 repository 집합의 합집합이며, 양쪽에 속하는 세션은 중복 없이 표시된다. 무관한 비공개 세션은 제외된다.
- A24-02: 같은 repository의 다른 폴더·linked worktree를 별도 공개 명령 없이 발견한다. 별도 clone·원격 repository 동일성은 이름/URL만으로 확정하지 않고 검증된 매핑을 사용한다.
- A24-03: “macmini에서 이 작업”을 검색하면 허용된 원격 후보의 머신·업무·branch·최신성·실제 핸들이 맞는다. 검색만으로 새 협업이나 업무 송신을 시작하지 않는다.
- A24-04: 후보를 확인한 사용자의 “a1과 협업” 한 지시로 내부 project 설정이나 중복 승인 없이 그 상대와 연결한다. a2·b1·b3 및 그 폴더의 권한은 새로 열리지 않는다.
- A24-05: 선택한 핸들과 실제 상대의 상관된 응답을 확인한 뒤 핸드셰이크 완료를 표시한다. 영수증만 있거나 동명/세대가 바뀌면 완료가 아니다.
- A24-06: timeout·busy·전송 결과 유실 뒤 같은 요청에서 답을 회수하고 중복 협업/업무를 만들지 않는다. 부모 계보와 무관하게 양방향 후속 협업이 된다.
- A24-07: 공개 철회·협업 해제·세션 종료·새 대화·동명 교체·같은 대화 resume을 구분한다. 미독·승인 오상속과 전체 경로/원문 추가 공개가 없다.
- A24-08: 맥북과 맥미니의 서로 다른 폴더에서 후보 탐색→사용자 선택→핸드셰이크→실제 작업 요청/회신을 한 trace로 검증한다. 기존 같은 repository 및 명시적 link/join/reach도 유지한다.

## 되돌리기

기존 repository·link/join/reach 권한과 원장·미독을 보존한다. 추가한 공개·협업 관계는 출처와 소유권을 기준으로 분리해 비활성화한다. 세션별 승인을 폴더 전체 허용으로 변환하지 않는다. 이 결정 변경은 후속 ADR로 남긴다.

## 결정 근거와 토론

2026-10-28 사용자 예시, 후보 집합 정정, “방금 설명한 내용으로 설계문서와 ADR, 구현목표를 확정지어”라는 지시로 확정했다. 에이전트가 먼저 제안한 ask/status 철자·짧은 기본 대기 정책을 사용자가 채택한 것으로 해석하지 않는다.
