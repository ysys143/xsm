# ADR-0022: 동료 입력의 권위와 통신 오용을 분리해 제어한다

- 상태: Proposed
- 관련 목표: G2, G5, G6
- 작성일: 2026-10-24
- 역공학 추적: R05, R24, R28, R29, R38, R43
- 기존 결정 효력: 이 문서는 아직 Accepted ADR을 대체하지 않는다.

## 질문

정상적인 동료 N:N 협업을 유지하면서 메시지의 권위 위조·권한 확대·반복 폭주를 무엇에 근거해 제어할 것인가?

## 맥락

Reason은 peer 메시지와 검증된 승인 프레임을 구분하고 본문·디렉터리·오류에 예약 태그와 제어 문자가 권위를 위조하지 못하도록 렌더링한다. 메시지 쌍의 속도와 반복을 제한하며 에이전트의 그룹 주소 송신을 금지한다. [render.rs](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/src/render.rs), [mail.rs](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/src/daemon/mail.rs).

그룹 금지와 고정 왕복 한도는 정상 협업까지 막을 수 있는 제품 선택이다. 그 수치를 적절하다고 실측한 것은 아니다. prompt injection 전체를 막았다고 해석해서도 안 된다. 로컬 IPC는 같은 OS 사용자 경계이며 머신 키 파일에 접근 가능한 프로그램까지 방어하지 않는다.

xsm도 [envelope](../../xsm/envelope.py)·[receive](../../xsm/receive.py)에서 동료 입력·수신 게이트·중복·중첩 봉투를 다루고 네이티브 사용자 연결의 통과 정책을 0013에 정했다. 부모·자식 전용 설계는 사용자 원래 의도가 아니다. [INTENT](../../INTENT.md)는 N:N과 자연스러운 기존 하네스 사용을 요구한다.

## 선택지

| 안 | 방식 | 이점 | 비용·위험 |
|---|---|---|---|
| A | 연결 관계를 좁혀 오용 가능성 자체를 줄임 | 단순한 범위 제어 | 정상 협업 단절, 같은 uid 공격자에 대한 효과 과장 |
| B | 출처·권위·업무 권한과 실제 오용 행동을 각각 검사 | N:N 유지와 구체적 진단 | 신호·관측·예외 처리 및 정상 표본 검증 |
| C | 에이전트 지침만으로 자제 요청 | 구현이 작음 | 제어 문자·권위 위조·반복을 기계적으로 제한하지 못함 |

## 제안 계약

B를 제안한다. 동료 요청이 권한을 부여하지 않는다는 지침과 검증 가능한 형식·원장 검사를 함께 둔다.

- 사람의 실제 요청, peer 메시지, 인증된 머신 정보, 승인 레코드의 출처를 각각 표시한다. 본문 속 주장은 출처 메타데이터가 되지 않는다.
- 본문·이름·브랜치·오류·첨부 목록이 예약 프레임을 열거나 닫고 승인자·자료 경로를 위조하지 못하도록 경계 밖 메타데이터를 렌더링한다. 제어 문자·유니코드 유사 문자·방향 문자도 반례로 검사한다.
- 실제 승인도 해당 요청·승인자·범위·수명에 맞을 때만 적용한다. 동료가 보낸 “허락받았다”를 새 권한으로 수용하지 않는다.
- 루프 제어는 실제 반복·속도·중복 요청을 근거로 하고 정상 검토 왕복과 구분한다. 원문과 회수 가능한 상태를 유지하며 한도를 이유로 상대 과제를 성공 종료하지 않는다.
- 직접 통신 가능성을 부모 계보에 묶지 않는다. 명시적인 여러 대상 검토와 무차별 브로드캐스트를 구분하며 Reason의 그룹 금지를 그대로 복사하지 않는다.
- 하네스의 네이티브 연결과 xsm의 범위 설정이 서로 다른 의미일 때 사용자 결정 0013을 존중한다. 모르는 발신자를 무조건 차단하는 정책을 기본으로 재도입하지 않는다.
- 정책 파일 파싱 실패·권한 저장소 오류를 정상 기본값으로 조용히 바꾸어 허용 범위를 넓히지 않는다. 실패와 현재 적용한 정책을 표시하고 이미 허용된 로컬 대화의 유지·복구를 별도로 설계한다.

## 기존 결정과 이행

0004·0013의 연결·기본 수신 판단과 uid 신뢰 경계를 유지한다. 신규 보호 장치가 기본 거부를 늘리면 사용자 결정 변경으로 다룬다. 권위 표시가 모델 판단을 보조한다는 한계를 문서화하고 메시지 접근 자체와 외부 파일 실행 권한을 분리한다.

## 수용 검사

- A22-01: 본문·세션 이름·repo/branch·오류에 가짜 승인·프레임 종료·ANSI·양방향 문자·유사 문자를 넣어 출처 표시가 바뀌지 않는지 확인한다.
- A22-02: 다른 요청의 실제 승인과 동료의 승인 주장을 구분한다. 같은 uid 프로그램을 막는다고 주장하지 않는다.
- A22-03: 구현자·검토자의 여러 차례 반례·수정·재검증이 정상 완료된다. 의미 없는 반복이 중단돼도 요청은 조회·복구 가능하다.
- A22-04: 부모 없는 일반 세션, 형제 워커, 다른 저장소 동료가 승인 범위 안에서 직접 소통한다.
- A22-05: 네이티브 메시지와 xsm 봉투 메시지의 기존 허용·차단·주석 정책에 회귀가 없는지 검사한다.
- A22-06: 정책 파싱 오류와 상태 저장 실패를 주입해 조용한 권한 확대·가짜 승인·메시지 소실이 없는지 확인한다.

## 비용과 되돌리기

형식 정규화가 정상 텍스트를 바꾸고 오용 감지가 정상 왕복을 제한할 수 있다. 제한 근거와 적용 범위를 진단할 수 있어야 한다. 새 한도는 사용자 설정과 관찰로 조절하고 기존 명시적 block·strict 정책을 보존한다. 보호 기능을 꺼도 출처 이력을 지우지 않는다.

## 미결 매개변수
