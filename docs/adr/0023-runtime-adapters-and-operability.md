# ADR-0023: 설치와 하네스 어댑터의 생명주기를 검증 가능하게 만든다

- 상태: Proposed
- 관련 목표: G1, G2, G3, G4, C1
- 작성일: 2026-10-24
- 역공학 추적: R01, R09, R16, R33, R34, R35, R36, R37, R38, R39, R40, R41, R42
- 기존 결정 효력: 이 문서는 아직 Accepted ADR을 대체하지 않는다.

## 질문

사용자가 별도 진입점·매뉴얼·수동 설정 없이 설치하고 기존 세션을 쓰게 하면서, 프로필·하네스·서비스·업데이트의 실제 상태를 어떻게 보장할 것인가?

## 맥락

Reason의 공개 엔진은 정적 바이너리, MCP·훅·플러그인 어댑터, 설정 병합·원본 백업·원자적 교체·설정 권한 유지, 선택적 로그인 서비스와 doctor를 제공한다. 오래 실행 중인 MCP는 데몬에 재접속하고 등록을 복원한다. tincan에서의 이동은 이전 경로·소켓을 연결해 기존 세션을 유지한다. [setup.rs](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/src/setup.rs), [client.rs](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/src/client.rs), [paths.rs](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/src/paths.rs).

설치 스크립트는 체크섬을 검사하고 macOS에서 기존 개발자 팀 서명을 유지하려 한다. standalone 자동 업데이트와 Reason CLI가 핀한 엔진의 업데이트 소유자가 다르다. 공개 엔진은 MIT OR Apache-2.0이고 NOTICE는 tincan 출처를 명시한다. 비공개 CLI의 공개 저장소는 없지만 설치 바이너리 내 JavaScript 여섯 모듈의 정적 분석은 수행했다. 로그인 서비스·호스팅 MCP 서버의 내부 구현은 얻지 못했다. [배포물 분석](../references/reason-network/cli-analysis.md), [공식 공개 범위](https://reasonmachines.com/network), [NOTICE](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/NOTICE).

실제 설치에서는 로그인·가입을 사용자가 직접 했고 Codex 훅 신뢰도 사용자 승인이 필요했다. serve Claude의 기본 MCP 부재·일반 Codex 다중 홈 전달 실패·일부 상태 등록 실패가 있었다. 자동 설치가 모든 기존 세션의 정상 참여를 증명하지 않는다. xsm의 [install](../../xsm/install.py), [identity](../../xsm/identity.py), [adapters](../../xsm/adapters.py), [probe](../../xsm/probe.py)와 비교해야 한다.

## 선택지

| 안 | 방식 | 이점 | 비용·위험 |
|---|---|---|---|
| A | 하네스별 설치·동작 확인을 문서 절차로 유지 | 직접 제어·작은 구성 | 사람과 에이전트의 수동 지식·설정 누락 |
| B | 명시적 어댑터 능력 계약·설치 소유 기록·실제 경로 진단 | 기존 하네스에서 자동 참여와 복구 | 버전별 적합성·설정 병합·롤백 유지 |
| C | 자체 상주 런타임으로 모든 하네스를 실행 | 시작 환경 통제 | 기존 세션·기성 하네스 공존 요구와 충돌 |

## 제안 계약

B를 제안한다.

- 어댑터는 발견·발신자 식별·수신·깨우기·작업 중 개입·회신·사용자 질문·첨부·재개 지원 능력을 보고한다. 도구 목록에 필드가 있다는 사실과 실제 작동을 구별한다.
- CODEX_HOME/Claude 홈·native conversation·프로세스 세대·작업 폴더를 호출과 전달 명령에 끝까지 보존한다. 공유 MCP는 매 호출 문맥을 사용하고 상속 환경이나 최신 이웃만으로 권한을 정하지 않는다.
- 설치기는 기존 설정과 소유 항목을 기록하고 필요한 부분만 병합한다. 원본 백업·권한·사용자 변경을 보존한다. 제거 시 자기 항목만 거두며 현재 설정 전체를 과거 백업으로 덮어쓰지 않는다.
- 설치와 가입의 각 완료 단계를 기록한다. 로그인 완료·머신 가입·계정에 팀 등록·하네스 설정·기존 세션 반영을 같은 성공으로 합치지 않는다. 선택적 제어 서비스 실패가 이미 승인되고 성립한 로컬/직접 연결을 중단시키지 않게 하며, 미완 단계는 명확히 남긴다. 비동기 완료 작업은 원 가입 흐름과 결속하고 다른 계정의 기존 자격 증명을 덮어쓰지 않는다. 완료 저장 직전에도 flow ID·대상·세대를 대조하며 lock 또는 pending 파일의 존재만으로 대신하지 않는다.
- 로그인·가입·훅 신뢰·권한 규칙 변경은 각자의 승인 경계를 유지한다. 이미 주어진 의사를 재사용하되 설치 완료를 이유로 새 권한을 묵시적으로 부여하지 않는다. 여러 프로필 중 어느 것이 연결됐는지 표시한다.
- 기존 세션 참여와 새 세션 참여를 각각 확인한다. 재시작이 필요한 경우 이유와 현재 사용할 수 있는 경로를 제공한다. 기존 사용자 세션을 임의로 종료해 설치를 완료하지 않는다.
- 장기 연결은 재접속·재등록·상태 하향·실패 회수 경로를 가진다. 헬스체크용 일회성 MCP 연결은 불필요한 상주 주소를 증식시키지 않는다.
- doctor는 설정 존재, 훅 신뢰, 프로세스/소켓 생존, 대상 홈 일치, 실제 요청·수신·회신 증거를 별도 단계로 표시한다. 기능 진단은 승인된 시험 대상이나 격리 fixture로 수행하고 다른 실제 에이전트를 임의로 깨우지 않는다.
- 빌드·설치·구동·출처·관측 버전을 기록한다. 네트워크 엔진 업데이트·CLI 업데이트·설정 마이그레이션의 소유자를 구분한다. 핀된 구성과 standalone 구성을 같은 방식으로 자동 교체하지 않는다.
- 공급 경로의 체크섬·서명·출처와 라이선스를 보존한다. 체크섬 파일을 같은 배포처에서 받는 것이 독립된 서명 검증과 같다고 주장하지 않는다. 실제 코드 수입은 출처와 수정 이력을 남긴다.

어댑터 능력은 하네스 이름만으로 정하지 않고 해당 홈·대화·실행 모드의 관측과 결속한다.

| 능력 | 진단에 필요한 근거 |
|---|---|
| 호출자 식별·폴더 식별 | 실제 호출 meta·등록·네이티브 대화 대조 |
| 유휴 깨우기 | 추가 사용자 입력 없는 시험 요청의 수신 |
| 작업 중 전달 | 실행 중 도구/턴 경계에서 원 요청을 받은 기록 |
| 동기 질문·비동기 회신 | 원 요청 ID와 실제 답의 상관관계 |
| FYI | 깨우지 않음과 이후 자연 소비를 각각 확인 |
| 사용자 판단 | 실제 표시·응답 출처와 요청 결속 |
| 첨부 | 해당 호출자의 정상 자료 수신과 금지 자료 거절 |
| 재개·오류 복구 | 같은 대화·홈·미독·결과의 수명 확인 |

지원하지 않음과 아직 검증하지 못함은 구분한다. daemon·MCP·훅이 설치돼 있다는 진단만으로 위 능력을 모두 true로 만들지 않는다.

## 기존 결정과 이행

0003의 별도 필수 런타임 금지와 0010의 워커 소유 경계를 유지한다. 0001의 탐색 예산·0011의 관측 비용과 원문 비저장 정책도 고려한다. 원격에 선택적 서비스가 필요하면 0021의 별도 결정으로 연결한다. 설치가 변경한 allow·훅 그룹의 승인은 실제 구현 시 받으며 이 ADR 작성으로 승인된 것이 아니다.

## 수용 검사

- A23-01: clean 설치·이미 설치·다른 홈·여러 홈·기존 세션·새 세션을 각각 검사하고 실제 첫 왕복까지 기록한다.
- A23-02: 사용자 설정이 있는 상태에서 설치·재설치·업데이트·제거를 수행해 소유 항목만 달라지는지 대조한다.
- A23-03: 공유 MCP의 두 스레드, 다른 홈의 같은 ID, 상속된 타 하네스 환경에서 실제 발신자·첨부 루트·전달 홈을 확인한다.
- A23-04: 서비스 중단·MCP 재접속·훅 신뢰 없음·소켓 없음·오래된 API·하네스 버전 변화에서 실제 능력과 진단 표시가 일치한다. 로그인 완료 뒤 가입/설정 실패, 원 대기 종료 뒤 finisher 완료, 이전 로그인과 새 로그인 응답 경쟁, 선택적 계정 등록 실패를 각각 검사한다. 응답 대기 중·성공 응답 후 저장 직전 pending의 flow ID를 교체해 이전 결과가 새 흐름에 적용되지 않는지 검사한다.
- A23-05: 잘못된 체크섬·개발자 팀 서명 불일치·중단된 업데이트·설정 병합 실패에서 기존 동작과 복구 자료를 보존한다.
- A23-06: 기본 CLI serve의 MCP·회신·후속 문맥·권한 경계를 따로 시험한다. 보정 조건 성공을 기본 조건 성공으로 보고하지 않는다.
- A23-07: 진단을 실행해도 자격 증명·초대·원문 개인정보가 공개 로그에 남지 않고 실제 사용자 세션이 종료되지 않는다.
- A23-08: 이전 버전의 MCP·소켓을 사용하는 세션을 유지한 채 상태 위치와 어댑터를 업그레이드한다. 마이그레이션 중 실패하면 이전 경로가 계속 읽히고 사용자 설정이 보존되는지 확인한다.

## 비용과 되돌리기

하네스별 버전 변화와 설치 행렬을 유지해야 한다. 백업·소유 기록·다중 프로필·마이그레이션 지원은 배포 복잡성을 늘린다. 재접속이 모호한 기존 전송을 무조건 재실행하지 않도록 0018과 연결한다. 되돌리기는 소유 항목·이전 reader와 호환되는 상태·이전 바이너리를 이용하며 사용자 설정을 통째로 복원하지 않는다.

## 미결 매개변수

지원 하네스·OS 행렬, 자동 업데이트 기본값, 진단의 능동 시험 수준, 어댑터 API 안정성, 설정 백업 보존과 이전 형식 호환 기간은 미결정이다.
