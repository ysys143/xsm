# ADR-0026: 팀 보드는 xsm doc이 소유하고 channel은 대체 뒤 제거한다

- 상태: Accepted
- 관련 목표: G6, G7
- 작성일: 2026-10-30
- 결정자: 사용자
- 관련: [ADR-0005](0005-channel-thread-store.md), [ADR-0006](0006-shared-document-editing.md), [ADR-0014](0014-shared-board.md), [ADR-0025](0025-team-and-multi-recipient-dm.md), [설계 메모](../plan/collaboration/team-communication-memo.md)
- 적용 범위: 제품 계약. 0.5.1에서 팀 보드·결재 기록을 구현하고 기존 channel을 제거했다. 검증 범위와 한계는 [진행 기록](https://github.com/ysys143/xsm/blob/a124b22782d68c1541f6dd5893a57bbe6797b926/docs/plan/collaboration/team-implementation-progress.md)과 [TESTPLAN §14](../xsm/TESTPLAN.md#14-팀-보드-결재-인수인계-051)를 따른다. 아래 맥락과 구현 과제는 결정 당시 기록이다.

## 질문

팀의 합의·작업 분담·진행을 여러 에이전트가 함께 쓰고 읽는 기록을 무엇으로, 어디에 두며, 기존 `xsm channel`과 `xsm doc`은 어떻게 하는가?

## 맥락

- 사용자 원칙: 공유 기록은 주로 에이전트용이고(합의·분담·진행), 컨텍스트 낭비를 막아야 하며, 한 에이전트만 쓰는 구조는 맞지 않고, 소통이 분산되는 것은 위험하다. `xsm doc`·`xsm channel`·마크다운 보드 셋을 모두 가져갈 이유는 없다.
- `xsm channel` 게시는 두 머신에서 5건·0건이었고 에이전트끼리의 소통에 쓰인 적이 없다. `xsm doc` 문서는 두 머신 어디에도 없다.
- `pg_cuvs` 팀은 조율자 한 명이 쓰는 `PHASE.md`를 상태판으로 썼다.
- 기존 `xsm_decide`는 사용자의 결재를 `xsm channel`의 `decision`으로 남긴다. 에이전트는 `decision`을 직접 쓸 수 없다.

## 선택지

### A. 마크다운 보드를 에이전트가 직접 편집
- 장점: 에이전트의 기본 행동(Edit·patch)과 같고 마찰이 적다. 사람이 열고 고치기 쉽다.
- 단점: 이력은 git에 기대고, 결재 진위를 보장하지 못한다(누구나 "결재됨"을 쓸 수 있다). 셸 쓰기와 구조 손상을 막지 못한다.

### B. `xsm doc`이 보드를 소유
- 장점: 기여가 불변 노드라 구조상 충돌·유실이 없고 이력이 남는다. 사용자 승인(`endorsed`)이 있다.
- 단점: 지금의 렌더는 항목별 현재 상태를 만들지 못한다. 쓰기 마찰이 크다.

### C. `xsm channel`을 보드로 확장
- 장점: 덧붙이기 기록과 `decision` 보호가 이미 있다.
- 단점: 머신 밖으로 나가지 않고 사람이 보기 어렵다. 현재 상태가 아니라 기록 전체를 읽어야 한다.

## 근거

- [S11](../spikes/S11-results.md) 마크다운 직접 편집, 20회: 유실 0. 오래된 읽기로 Edit 실패 7건 모두 다시 읽고 성공(Claude). Claude 셸·Write 0/50, Codex 셸 4/19(21%). 항목 제목 덮어쓰기 1건. 워크트리마다 보드가 갈라짐(반영 0/5), 공통 절대 경로면 5/5.
- [S11b](../spikes/S11b-results.md) `xsm doc` 보드, 20회: `doc add` 73회 모두 보존, 렌더 파일 직접 편집 0. 렌더만 고친 외부 수정은 재렌더에서 5/5 사라짐, 노드 주입은 5/5 보존. `report` 태그 기여가 렌더 대표 본문을 차지해 초기 항목 제목이 사라진 경우 4회. 실패한 도구 호출 46건. `doc next` 사용 0.
- [S12](../spikes/S12-results.md) 걸러 읽기, 152회: haiku 전 라벨 재현율 100%, luna 전제 변경 95.5%. 표본이 쉬워 판정에 쓰지 않는다.
- [S10](../spikes/S10-results.md): "채널에 `taking`을 남겨라"는 한 줄 규칙으로 1:1 메시지가 채널로 통째로 옮겨 갔다. 장소를 여럿 두면 안내 한 줄로 소통이 옮겨 다닌다.
- 실험의 판정 기준(S11 10%, S12 90%·95%·10%p)은 제안값이며 사용자가 승인한 기준이 아니다. 이 결정은 기준 통과가 아니라 결과 비교로 내렸다.

## 결정

B를 택하고 렌더를 고친다(사용자 결정 2026-10-30).

**보드**
1. 팀 보드는 `xsm doc`이 소유한다. 기여는 불변 노드이고, 보드는 항목별 최신 상태로 렌더한다. 같은 항목의 동시 노드는 덮지 않고 함께 표시한다.
2. 보드는 xsm이 정한 공통 경로(예: `~/.xsm/teams/<팀>/`)에 둔다. 워크트리마다 갈라지지 않는다. 이력은 doc 노드가 맡고 머신 간에는 xsm이 노드를 맞춘다.
3. "남을 움직이려면 DM, 모두가 알아야 할 사실이면 보드. 둘 다에 쓰지 않는다"를 스킬에 넣는다. 팀 전체에 해당하는 결정을 DM으로 받으면 보드에 옮기고 DM에는 위치만 남긴다.
4. 기존 지시로 쓰던 상태 파일(`PHASE.md` 류)은 따로 두되 적극적으로 동기화한다. 그 파일에 "에이전트 간 작업용 정본은 xsm doc 보드에 있다"고 알린다. 상태 파일은 사람이 진행 단계를 확인하는 용도다.
5. 회의록을 따로 두지 않는다. 합의 결과는 보드 항목으로, 결재는 결재 기록으로 남고 논의 과정은 노드 이력에 남는다.
6. 싼 모델 서브에이전트의 걸러 읽기는 어려운 표본으로 다시 실험한 뒤 스킬 권장 여부를 정한다.

**결재 기록**
7. 결재 기록은 팀 보드와 함께 둔다. `xsm_decide`는 결재를 보드 옆 보호된 기록에 남기고, 보드 항목은 그 기록 ID를 가리킨다. 보드와 함께 머신 간에 맞춰 원격 팀원도 확인할 수 있게 한다.

**추가 사용자 결정 — 승인 복구(2026-10-31)**
- 네이티브 답 재판독을 팀 결재의 공식 경로에 포함한다. 런타임·설정 홈·대화, 질문 ID·질문 원문, 유효 시간과 미사용 여부가 검증돼야 한다. 출처는 `native-user`로 기록한다. 에이전트가 인용한 승인 문장은 근거가 아니다.
- 평문 답은 유효한 요청이 하나일 때만 결속하며, 여러 승인 질문은 질문별로 독립 결속한다.
- 이 결정의 구현과 실제 하네스 검증은 [TESTPLAN 15절](../xsm/TESTPLAN.md#15-승인-결속-25)에 기록한다. 기존 0.5.1 실측으로 이 경로까지 검증됐다고 해석하지 않는다.

**기존 기능**
8. 기존 `xsm channel`은 팀·보드·결재 기록이 준비되고 `xsm_decide`가 옮겨진 뒤 제거한다. 그전까지 문서에 "검토 중, 제거 예정"으로 표시한다.
9. `xsm doc`의 공동 산출물 용도(ADR-0006)는 유지하고 보드 용도를 더한다.

**기각**
- A: 보호 경로가 기본 행동과 같다는 장점은 S11에서 확인했지만, 결재 진위와 이력을 따로 만들어야 하고 Codex 셸 쓰기 21%와 구조 손상을 막지 못한다. S11b에서 doc은 우회 0·유실 0이었다.
- C: 머신 밖으로 나가지 않고, 현재 상태를 읽으려면 기록 전체를 읽어야 하며, 소통 장소를 하나 더 만든다.

**구현에서 풀 것**: 항목 개념과 항목별 렌더, `report` 태그가 보드 전체를 덮지 않는 렌더 규칙, 쓰기 마찰(태그 기본값, 빈 본문·잘못된 태그 안내), 샌드박스 Codex용 MCP 쓰기 도구, 사람의 직접 편집을 렌더 시점에 노드로 받아들이는 방식, 노드의 P2P 동기화.

**기존 결정과의 관계**
- ADR-0005(채널-스레드 기록 저장소)는 8번의 조건이 충족되면 Superseded가 된다.
- ADR-0006은 유지하며 보드 용도로 확장한다.
- ADR-0014(공유 메시지 풀과 시각 대시보드)의 에이전트용 공유 기록 부분은 이 결정이 정한다. 사람이 보는 대시보드와 외부 서비스 연동은 0014에 남는다.
