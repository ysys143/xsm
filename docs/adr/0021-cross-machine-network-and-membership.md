# ADR-0021: 원격 연결의 편의와 머신 인증을 분리된 전송 계약으로 제공한다

- 상태: Accepted (제품 방향·멤버십 요구사항 확정; ADR21 범위 구현·수용 검증 2026-10-30 종결)
- 결정일: 2026-10-29
- 결정자: 사용자
- 관련 목표: G4, G5, C1
- 작성일: 2026-10-24
- 비교 근거: [Reason 비교 노트](../references/reason.md)
- 기존 결정 효력: ADR-0003의 로컬 핵심 경로 데몬 비의존을 유지한다. ADR-0007의 기존 SSH 호환을 보존하면서 신규 원격 경로의 필수 SSH·프로젝트 짝짓기 전제를 대체한다.

## 질문

사용자가 사설 VPN이나 양방향 SSH 설정을 직접 조립하지 않아도 원격 세션에 도달하게 하면서, 기존 로컬 동작·가입 의도·머신 인증·업무 권한을 어떻게 보존할 것인가?

## 맥락

Reason은 머신별 iroh Endpoint와 공개키, LAN mDNS·NAT 통과·HTTPS 릴레이를 사용한다. 사설 IP를 배포하는 범용 VPN은 아니다. 멤버십은 서명된 admission/member/invite 기록을 복제하고 활성 멤버만 통신시킨다. 계정 증명은 이름과 머신 키의 결속을 표시하며 멤버십 및 업무 승인을 대신하지 않는다. [net.rs](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/src/net.rs), [team.rs](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/src/team.rs), [proof.rs](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/src/proof.rs).

재사용 팀 링크와 1회 코드의 의미가 다르고, 누구나 초대·제명할 수 있는 친구 팀 모델이다. 제명된 머신의 암호학적 권한이 모두 사라지는 강한 관리 모델로 설명하면 안 된다. 자체 릴레이 설정 시 기본 서비스 접속 경로도 달라진다. 0.12.11은 고정 UDP 포트·IPv4/IPv6 바인딩·점유 시 랜덤 포트 대체와 실제 포트 진단을 추가했다. 이전 0.12.10 실통신 표본과 구분한다.

[0007](0007-remote-transport-and-trust.md)의 xsm은 강제 명령 SSH 키와 양쪽 프로젝트 짝을 사용한다. 양방향 SSH가 전제이고 목록 병합은 없다. [remote.py](../../xsm/remote.py)는 발신 주장 대신 SSH 연결에서 origin을 정한다. 최초 단일 머신 조사 이후 두 물리 머신의 carrier 비교가 추가됐다. [P11 기록](../plan/collaboration/remote-decision.md)의 범위·한계를 보존하며 이를 신규 P2P 제품의 구현·안정성 증거로 해석하지 않는다.

## 검토한 선택지

| 안 | 방식 | 이점 | 비용·위험 |
|---|---|---|---|
| A | 기존 SSH 설정·짝짓기·진단을 개선 | 현재 신뢰·배포 모델 유지 | NAT·양방향 접근·키 설정의 제약 유지 |
| B | xsm 전용 선택적 P2P 엔진 | 의미와 수명 계약을 직접 통제 | iroh 바인딩·서비스·업데이트·릴레이 운영 비용 |
| C | 공개 Reason 엔진을 선택적 전송 백엔드로 연결 | 검증 가능한 기존 네트워크 구현 재사용 | 별도 멤버십·세션 주소·버전·권한 의미 번역 및 라이선스 관리 |
| D | 사설 VPN 위에서 기존 SSH 사용 | 범용 네트워크 도구 활용 | 사용자의 VPN 가입·접근 정책·SSH 설정 의존 |

## 확정 요구사항

사용자 결정(2026-10-29)으로 다음 제품 요구사항을 확정한다. 이 결정은 구현·배포·서비스 기동의 완료 판정과 별개다.

### 통신과 접속 경로

- 기본 원격 통신은 xsm 자체 P2P다. 인터넷 직접 연결, 선택적 Tailscale 주소, relay는 같은 P2P 프로토콜의 접속 경로다. Tailscale 설치나 SSH 접속을 신규 P2P 경로의 필수 조건으로 두지 않는다.
- 공개 relay를 기본 지원하고 자체 relay 주소 설정을 제공한다. Tailscale은 접속 경로 제공에 사용하며, 접속 사실만으로 xsm 멤버십·세션 권한을 부여하지 않는다.
- 기기 신원은 접속 주소와 분리된 기기키에 결속한다. 경로가 바뀌어도 같은 기기·세션 신원과 유효한 협업 관계를 재사용한다.
- 별도 xsm 계정 로그인은 필수가 아니다. 기기키와 유효한 초대로 가입하며 이름·표시명만으로 신원이나 권한을 인정하지 않는다.

### Reason식 멤버십

- 멤버의 단위는 기기다. 기존 활성 멤버 누구나 초대·기기 추가·제명을 할 수 있으며 멤버십 변경은 기기키의 서명과 검증으로 결속한다.
- 소유자·관리자 권한 계층은 두지 않는다. 최초 생성 기기는 서명된 멤버십 신뢰의 출발점이며 운영 권한을 독점하지 않는다.
- 유효한 초대가 가입 자격을 부여한다. 온라인 멤버가 이를 검증해 가입시키며 가입 때마다 별도 관리자 승인을 요구하지 않는다. 에이전트는 사용자의 가입·초대·제명 의도를 대행하며 피어 메시지를 사람의 승인으로 취급하지 않는다.
- 재사용 팀 링크와 일회용 초대를 구분한다. 만료·회수·중복 사용·응답 유실 후 같은 기기의 재시도·재가입을 구분한다. 초대·키를 일반 목록과 로그에 노출하지 않는다.
- 상호 신뢰하는 멤버들의 네트워크를 전제로 한다. 제명과 초대 회수의 실제 효력을 명시하며 악의적인 기존 멤버까지 통제하는 강한 암호학적 제명 보장은 주장하지 않는다.

### 기존 세션 계약과의 연결

네트워크 가입, 세션 공개, 선택한 상대와의 협업, 파일·모델 실행 권한은 별개다. ADR-0024의 후보 합집합·사용자 선택·상관된 핸드셰이크와 공개 범위는 그대로 적용한다. 아래 운영·복구 요구도 유지한다.

- 로컬 기능은 기존 하네스·훅·파일·CLI로 유지한다. 원격을 켠 사용자에게만 네트워크 연결과 필요한 서비스의 수명·중지 방법을 설명한다. 네트워크 장애가 로컬 메시징을 중단시키지 않는다.
- 백엔드가 인증한 머신 신원을 origin으로 삼고 봉투의 이름·from-mode를 권한 근거로 삼지 않는다. 신원 확인 실패와 업무 권한 부족을 구분한다.
- 가입 의도, 초대 자격, 가입할 팀/머신, 공개할 세션 범위를 확인한다. 초대 소지·계정 이름 검증·머신 멤버십·프로젝트 권한은 서로 다른 사실이다.
- 팀 전환이나 가입 응답이 유실되면 요청한 팀 ID·머신 신원·현재 소속을 대조한다. 이전 팀이 아직 존재하는 상태를 새 가입 성공으로 해석하지 않는다. 전환 실패 후 원래 네트워크로 복구할 수 있는지 표시한다.
- 초대의 재사용·만료·회수·재가입, 기존 멤버 제명, 오프라인 멤버의 최신 정책 수신과 키 교체를 명시한다. 링크·증명·개인키를 일반 로그나 ADR에 남기지 않는다.
- repo·branch·doing·경로는 별도의 공개 정책을 따른다. 네트워크 가입만으로 원치 않는 저장소나 기존 미등록 세션을 편입하지 않는다.
- 자동 경로 선택은 직접 연결·릴레이·프록시·SSH의 실제 경로와 하향 이유를 진단에 남긴다. 고정 포트 실패 뒤 대체한 포트도 표시한다. 사용자가 연 포트가 적용된 것처럼 보고하지 않는다.
- 원격 MCP/호스팅 어시스턴트는 로컬 P2P와 별도의 신뢰·자격 증명·데이터 경로를 가진다. 이 경로를 켜지 않은 로컬 사용자가 클라우드 서비스에 의존하게 만들지 않는다.
- 공개 Reason 엔진은 비교 근거로 보존한다. Reason의 멤버십 방식을 따르는 결정은 Reason 엔진 바이너리를 제품 backend로 채택하는 결정이 아니다.

## 기존 결정과 이행

신규 원격 경로의 선택적 P2P 서비스와 기존 SSH 호환을 확정했다. 로컬 핵심 경로는 네트워크 서비스에 의존하지 않는다. 현재 설정·SSH pairing을 자동 변환하거나 삭제하지 않는다. 새 원격 기능을 켜도 로컬 scopes를 넓히지 않는다. 0014의 공유 보드·외부 데이터 수집 선택은 이 ADR이 결정하지 않는다.

## 수용 검사

확정 요구사항은 기존 A21/A24 조건에 다음 실행 예시를 결속한다. 기존 70개 조건을 삭제하거나 새 결정만으로 통과시키지 않는다.

- A21-01/04: Tailscale 없는 두 기기에서도 P2P 직접 연결 또는 relay로 왕복한다. Tailscale 주소를 쓰는 경우에도 같은 프로토콜·기기 신원·세션 핸들을 유지한다.
- A21-02: 최초 생성 기기가 오프라인이어도 다른 활성 멤버가 초대·추가·제명을 수행한다. 유효한 초대로 가입할 때 계정 로그인이나 별도 관리자 승인을 요구하지 않는다. 잘못된 네트워크·만료/회수 초대는 허용하지 않는다.
- A21-05/07: 공개 relay 기본 동작과 자체 relay 설정·경로 진단을 구분하고 네트워크 장애 중 로컬 기능을 유지한다.
- A21-06/A24: Tailscale 접속이나 네트워크 가입만으로 ADR-0024의 후보 집합 밖 비공개 세션·새 협업·파일/실행 권한이 열리지 않는다. 기존 공개 후보 합집합·사용자 선택·실제 핸드셰이크를 유지한다.

- A21-01: LAN·같은 NAT·서로 다른 NAT·UDP 차단·HTTPS 프록시·자체 릴레이·SSH 전용 환경에서 실제 경로와 왕복을 기록한다.
- A21-02: 제3자·제명 머신·위조 이름·유효 계정 증명이지만 잘못된 팀·만료/회수 초대·오프라인 재접속을 검사한다. 이전 팀이 남아 있는 상태의 가입 응답 유실과 전환 실패·복귀 실패도 구별한다.
- A21-03: 양방향 SSH가 불가능한 환경을 포함해 A/B/C/D의 설치 단계와 사용자 개입을 비교한다. 자동 설정했다는 로그만으로 연결 성공을 판정하지 않는다.
- A21-04: 두 물리 머신의 다른 홈·런타임에서 실제 세션을 찾아 질문·후속·직접 회신을 수행한다. 같은 호스트의 두 프로세스 검사는 별도 표기한다.
- A21-05: 원격 서비스·릴레이를 끊어도 로컬 질문·응답은 유지된다. 중지·제거 뒤 리스너와 소유 서비스 상태를 확인한다.
- A21-06: 네트워크 가입 전후 메타데이터 공개와 폴더 제외를 대조한다. 비공개 CLI·호스팅 MCP는 관찰 가능한 범위와 미검증을 표시한다.
- A21-07: 고정 UDP 포트 점유·IPv6 부재·주소 변경에서 대체 결과와 실제 바인딩을 대조한다.

## 비용과 되돌리기

P2P는 VPN 설정 부담을 줄일 수 있지만 상주 네트워크 프로세스·릴레이·키·초대·업데이트 비용을 만든다. Reason 백엔드 재사용은 이 비용을 없애지 않고 다른 구성 요소에 배치한다. 백엔드를 끄면 기존 로컬·SSH 동작으로 돌아가고 진행 중 원격 outbox는 내보내거나 명시적으로 정리할 수 있어야 한다. 키 폐기·제명은 되돌리기 어려운 사용자 작업으로 취급한다.

## 후속 구현 매개변수

제품 방향·멤버 관리 권한·계정 비필수·공개 relay 기본/자체 설정 지원은 확정됐다. 라이브러리·버전, 공개 relay의 구체 주소·공급·운영 근거, 초대 형식·수치·키 저장, 리스너·포트와 경로 선택 알고리즘은 후속 구현에서 정한다. 이를 D12 사용자 선택을 다시 받는 사유로 삼지 않는다. 세션 공개 범위는 ADR-0024를 따르며 원격 repository 동일성의 검증 방법은 계속 구체화해야 한다. 실제 서비스·권한·유료 자원 변경 승인은 별개다.
