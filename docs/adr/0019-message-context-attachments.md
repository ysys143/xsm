# ADR-0019: 메시지에 필요한 자료 사본을 명시적으로 전달한다

- 상태: Proposed
- 관련 목표: G2, G4, G6, G7
- 작성일: 2026-10-24
- 비교 근거: [Reason 비교 노트](../references/reason.md)
- 기존 결정 효력: 이 문서는 아직 Accepted ADR을 대체하지 않는다.

## 질문

작업 요청과 함께 작은 문서·코드·로그를 보내면서 발신자 작업 범위, 수신 사본, 버전과 보존을 어떻게 명확히 할 것인가?

## 맥락

Reason의 files 입력은 본문과 같은 메시지에 작은 텍스트 파일을 실어 수신 컴퓨터의 사본 경로를 보여 준다. 실제 공동 문서 검토에서 자료 운반이 편했다. 수신 사본은 원본과 자동 동기화되지 않았으며 정의·발췌·출처를 구성하는 책임은 여전히 발신 에이전트에 있었다. [실사용](../../deliverables/reason-workflow-experience.md).

공개 구현은 송수신 양쪽의 크기·이름 검사, 프로젝트 루트·숨김 경로·공유 제외 검사, 수신 로컬 ID로 만든 사본 디렉터리, 보존·용량 제한과 files 지원 협상을 갖는다. 구버전에는 가능한 경우 본문으로 풀어 쓰고 불가능하면 명시적으로 거절한다. [files.rs](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/src/files.rs), [for_machine](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/src/daemon/mail.rs).

단, mcp.rs의 agent_files는 매 호출 session key를 받지 않고 프로세스 cwd를 사용한다. 공유 MCP의 호출별 작업 폴더와 자료 루트 불일치가 조건부 결함 후보였다. 원래 실험에서 실제 하네스의 다중 저장소 프로세스 공유는 재현하지 않았다.

이번 합성 MCP 시험에서는 두 호출 ID와 서로 다른 hook cwd를 등록했다. B 대화와 B 폴더는 식별됐지만 B의 정상 파일은 프로세스 A 루트 기준으로 거절됐고 A 파일만 전달됐다(공개 엔진을 합성 MCP 세션으로 시험한 관측). 이 구성의 불일치는 재현됐지만 실제 하네스가 같은 공유 단위를 사용하는지는 여전히 별도 검증 대상이다. 정보 유출이나 모든 첨부 실패로 확대하지 않는다.

xsm의 text-file은 본문 입력이고 [mcp](../../xsm/mcp.py)에는 첨부 입력이 없다. [doc](../../xsm/doc.py)는 공동 문서의 이력과 정본을 관리하므로 첨부 운반으로 대체하지 않는다.

## 선택지

| 안 | 방식 | 이점 | 비용·위험 |
|---|---|---|---|
| A | 본문과 로컬 경로만 전송 | 현재 방식과 단순한 구현 | 다른 머신에서 경로가 무의미하고 자료 버전 불명 |
| B | 제한된 텍스트 사본과 출처 메타데이터를 메시지에 결속 | 검토 자료를 명시적으로 공유 | 파일 정책·할당량·보존·호환성 필요 |
| C | 공용 파일시스템이나 객체 저장소를 필수로 사용 | 큰 자료·공유 접근 가능 | 별도 서비스·자격 증명·원본 변경 추적 비용 |

## 제안 계약

B를 제안한다. 큰 자료의 링크 전달은 유지하며 C를 기본 의존성으로 요구하지 않는다.

- 본문에 목적·검토 질문을 두고 첨부에는 이름·콘텐츠 다이제스트·출처 버전·크기를 결속한다. 경로가 있다는 이유로 상대에게 읽기 권한이 있다고 가정하지 않는다.
- 발신 파일 접근은 같은 호출에서 확정한 신원·하네스 권한·공유 범위를 따른다. 작업 폴더는 상대경로와 출처를 해석하는 데 사용한다. 허가된 다른 폴더·임시 산출물·숨김 일반 설정 파일도 지원한다. MCP 프로세스 cwd나 이웃 세션의 루트를 권한 근거로 대신 쓰지 않는다. 문자열 경로와 실제 경로, 심볼릭 링크, 아직 없는 하위 경로를 대조한다.
- 에이전트가 원래 읽지 못하는 파일을 통신 도구가 대신 반출하지 않는다. 동료 요청은 파일 접근 권한을 확대하지 않는다. 파일 접근·명시한 공유 범위·자격 증명 경로·용량 정책을 발신 측에서 확인하고, 수신 측은 파일명·저장 위치·크기·보존을 검증한다. Reason의 프로젝트 밖·숨김 경로 거절을 xsm의 기본값으로 확정하지 않는다.
- 수신 사본은 신뢰할 수 없는 자료로 저장하고 실행하거나 자동으로 열지 않는다. 수신자가 만든 ID로 디렉터리를 정하고 경로 이동·동명·대소문자·유니코드 충돌을 처리한다.
- 상대 능력을 확인해 파일 전달, 명시된 본문 대체, 미지원 거절 중 결과를 보고한다. 첨부를 조용히 버리거나 자동으로 잘라 성공하지 않는다. 재전송에서도 같은 자료 다이제스트를 유지한다.
- 자료가 저장되지 못한 보류 요청은 승인만으로 delivered가 되지 않는다. 저장 실패·용량 초과·만료를 원 요청에 연결한다.
- 사본의 수명·원본과의 관계를 표시하고 수정본은 새 버전으로 전달한다. 공동 문서 노드와 연결할 수 있지만 자동 정본 병합은 하지 않는다.

## 기존 결정과 이행

0005·0006의 채널과 문서 규약은 그대로다. 첨부를 위해 저장소·원격 전송 포맷이 확장되므로 기능 협상과 구버전 읽기 계약이 필요하다. 기존 텍스트 전송은 첨부 없이 계속 동작한다.

## 수용 검사

- A19-01: CLI/MCP로 같은 텍스트·첨부를 보내 본문과 수신 사본의 다이제스트를 대조한다.
- A19-02: 하나의 MCP가 서로 다른 폴더의 두 세션을 처리할 때 각자의 정상 파일을 읽고 타 세션 파일은 접근하지 않는다.
- A19-03: 외부 경로·숨김 파일·심볼릭 링크·상위 경로·제외 폴더·동명 파일·유니코드 충돌을 검사한다. 허가된 저장소 밖 임시 산출물·숨김 일반 문서는 전달되고, 호출자 권한 밖 파일·제외 자료는 전달되지 않는지 양쪽 표본을 둔다.
- A19-04: 구버전·기능 미지원·본문 크기 초과에서 명시적 대체 또는 거절이 발생한다. 조용한 파일 누락을 실패로 잡는다.
- A19-05: 저장 실패·할당량 초과·승인 보류·재시작·만료 후 정리를 검사하고 원본 파일은 유지한다.
- A19-06: 수정본을 보낸 뒤 예전 사본이 자동 갱신되지 않음을 표시하고 버전별 검토 결과를 구별한다.

## 비용과 되돌리기

파일 사본이 늘고 민감 정보의 보존 면적이 커진다. 콘텐츠 다이제스트와 할당량 계산, OS별 파일명 차이를 유지해야 한다. 첨부 송신을 끄더라도 수신된 자료와 기존 메시지의 연결을 보존하고 정책에 따른 정리는 가능해야 한다. 실제 코드를 가져오면 MIT/Apache-2.0 및 NOTICE와 출처를 별도 보존한다.

## 미결 매개변수

지원 파일 형식·건별/인별/전체 한도·보존 기간·사용자의 수동 보존·본문 대체 동의·하네스 파일 권한 확인 방법은 논의 대상이다. Reason의 크기와 보존 값을 자동 채택하지 않는다.
