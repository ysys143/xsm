# ADR-0016: 에이전트의 요청과 응답을 일관된 도구 계약으로 제공한다

- 상태: Proposed
- 관련 목표: G2, G3, G6, C1
- 작성일: 2026-10-24
- 역공학 추적: R11, R12, R13, R14, R15, R16, R18, R36, R38, R39
- 기존 결정 효력: 이 문서는 아직 Accepted ADR을 대체하지 않는다.

## 질문

에이전트가 전송 경로·수신 절차를 조립하지 않고 질문, 비동기 위임, 방해하지 않는 참고 전달을 수행하게 하려면 어떤 인터페이스가 필요한가?

## 맥락

Reason CLI는 짧은 질문 한 호출에 실제 답을 반환했다. MCP는 목록·송신·수신·사용자 질문을 제공하며, push가 실제 가능한 Claude 세션에서는 수신함 도구를 숨긴다. 지침은 skill 원문에서 MCP 초기 지침으로 가져온다. 반면 MCP 송신은 항상 wake=true이며 CLI FYI와 기능 차이가 있다. 그대로 복사할 완성된 인터페이스는 아니다. [mcp.rs](https://github.com/reason-machines/reason-network/blob/b3557ff454cd26a04c2a18804ba83ae5db8b119d/src/mcp.rs).

xsm에도 비동기 송신, 수신 안내, 동료 직접 협업, priority와 채널 게시가 있다. 다만 [MCP 스키마](../../xsm/mcp.py)에는 송신 priority가 없고, [ledger.wait_for](../../xsm/ledger.py)는 답이 아닌 전달 상태를 기다린다. README의 답장 대기 설명과 차이가 있다. 일반 Codex의 답장은 CLI 실패 후 MCP로 복구된 실제 표본이 있다. [실제 비교](../../deliverables/xsm-reason-live-comparison-2026-10-23.md).

이번 조사에서는 설치 CLI 0.2.557 바이너리에 포함된 network-command와 ask-worker JavaScript의 경계를 추출해 정적으로 대조했다. 원문은 배포 라이선스를 확인하지 못해 저장소에 복제하지 않고 바이너리 SHA·오프셋·모듈 SHA와 분석을 [배포물 분석](../references/reason-network/cli-analysis.md)에 기록한다. Claude는 발신자별 warm 세션, 같은 발신자 직렬·다른 발신자 병렬, 유휴 세션 회수 구조를 가진다. Codex는 요청마다 새 exec이며 resume를 넘기지 않는다. 일반 세션의 문맥 유지와 serve의 문맥 유지는 같은 계약이 아니다.

후속 [원본 모듈 격리 실행](../references/reason-network/followup-findings.md)에서 재사용·직렬화·병렬화를 확인했다. 동시에 풀의 기존 6명이 모두 작업 중이면 일곱 번째 발신자의 새 워커를 유휴 회수해 실행하지 못하는 경로도 재현했다. 실제 7개 모델을 실행한 시험은 아니며, 전송·자식 런타임을 대체한 배포 모듈의 제어 흐름 관측이다.

## 선택지

| 안 | 방식 | 이점 | 비용·위험 |
|---|---|---|---|
| A | 기존 원시 송신·수신을 에이전트가 조합 | 계약 변화가 작음 | 경로 선택·상관관계·폴링 규칙을 계속 기억 |
| B | 공통 메시징 계약 위에 질문·비동기·참고 전달을 제공 | 목적별 호출이 명확하고 기존 원장 활용 | 대기·취소·여러 답·호환 스키마 설계 필요 |
| C | 도구가 워크플로와 역할 배정까지 소유 | 운영 자동화 가능 | 사용자 기존 하네스 및 0003·0010의 소유 경계와 충돌 |

## 제안 계약

B를 제안한다. 아래 필드는 개념 계약이며 실제 CLI 명칭과 스키마는 사용자 검토 전까지 확정하지 않는다.

- 짧은 질문은 request ID에 결속된 실제 회신을 반환한다. 전송 영수증만 받으면 답변 완료로 반환하지 않는다. 제한 시간에는 요청 ID·현재 상태·나중에 답을 회수할 방법을 반환한다.
- 비동기 요청은 즉시 식별자를 반환하고 수신·실패·결과가 같은 요청에 이어진다. 기존 kind/reply_to/outcome을 보존한다. 과제 결과는 수신자의 보고이며 독립 검증과 구별한다.
- 참고 전달은 깨우기 여부와 수신 우선순위를 명시한다. CLI/MCP/어댑터에서 표현 불가능한 의미는 지원하지 않는다고 알려야 한다. 실제 하네스가 무기상을 보장하지 못하면 보장한 것처럼 응답하지 않는다.
- 공통 필수 입력은 대상·본문이다. 기존 단순 송신 호출은 유지한다. 도구가 알 수 있는 발신 홈·스레드·회신 주소·전송 경로를 모델이 입력하도록 요구하지 않는다.
- 도구 노출은 확인한 환경 능력에 맞춘다. 자동 수신이 확실하면 불필요한 수동 조회 도구를 숨길 수 있으나 경로 하향 시 다시 회수 가능해야 한다. 전체 기능 삭제나 진단 경로 은폐로 구현하지 않는다.
- 메시징 지침은 하나의 원문에서 생성하고 설치 문서·MCP에 같은 의미를 제공한다. 메시징하지 않는 일반 작업의 계획·역할·종료 정책을 바꾸지 않는다.
- 대기 취소는 과제 취소나 워커 종료가 아니다. 실행 취소는 별도 의사와 지원 능력이 필요하다.
- 같은 주소로 후속 요청할 때 같은 네이티브 대화가 유지되는지 표시한다. 비공개 serve의 지속성을 주소만 보고 추론하지 않는다.
- warm 협력자 재사용 시 어떤 요청들이 문맥을 공유하는지 표시한다. 발신자별 직렬화와 서로 다른 업무의 병렬화를 분리하고, 독립 검토에 이전 실행자의 문맥이 섞이지 않게 한다. Reason이 임시 ask 주소를 한 발신자 그룹으로 합치는 정책을 자동 채택하지 않는다.
- 수신 확인과 실행 수락을 구분한다. 용량이 가득 차면 보관·대기·명시적 과부하 중 실제 상태를 반환하고, 방금 수락한 워커를 유휴 회수해 일반 답으로 끝내지 않는다. 과부하 재시도는 같은 원 요청을 참조한다.

질문 호출의 반환 계약은 다음 정보를 구분한다. 구체적인 필드 이름은 예시이며 기존 send 응답을 이 구조로 즉시 교체한다는 결정은 아니다.

| 정보 | 필수 의미 |
|---|---|
| request ID | 이후 조회·회신·취소가 참조할 같은 요청. 도구가 생성 |
| transport 상태·증거 | 0018의 실제 관측 단계. 답변 완료와 별개 |
| reply ID·reply_to·본문 | 해당 요청에 연결된 실제 회신. 없으면 답변 미완 |
| claims | 실제 반환한 reply ID의 정본에 대한 기존 owner/generation/digest·ACK token. 읽은 뒤 기존 ACK를 직접 호출하며 token 획득만을 위한 inbox 재호출은 필요 없다. 자동 ACK하지 않고 무관한 미독을 claim하지 않는다. 이미 ACK한 답은 재claim 없이 조회되며 cached-only/claim 실패도 답을 숨기지 않고 진단·회수 위치를 남긴다. 취소·출력 실패는 해당 미확인 claim을 해제한다. |
| 대기 종료 사유 | 회신·기한·호출자 취소·전송 거부·연결 오류를 구별 |
| task outcome·보고 주체 | 명시적 과제 결과가 있을 때만. 일반 질문에 성공 결과를 만들어 넣지 않음 |
| 후속 회수 위치 | 대기 기한이나 취소 뒤에도 같은 요청의 답을 회수할 수 있는 경로 |

CLI와 MCP는 이 계약의 의미를 공유한다. 호출 하나가 제한 시간 때문에 끝났어도 같은 요청을 다시 보내는 대신 먼저 그 ID의 상태와 답을 회수한다.

## 기존 결정과 이행

0002의 전달 영수증 의미, 0005의 채널, 0006의 공동 문서, 0010의 워커, 0012의 미결 조정 모델을 흡수하거나 대체하지 않는다. 질문 편의 계층은 기존 메시지 계약 위에 추가한다. 기성 하네스의 작업자 소유권을 가져오지 않는다. CLI/MCP 선택 부담은 어댑터에서 해결하되 진단 기록에는 실제 경로를 남긴다.

## 수용 검사

- A16-01: 같은 입력의 CLI/MCP 질문이 동일한 실제 답과 원 요청 ID를 반환한다. 영수증만 있는 반례는 성공 답변이 아니다.
- A16-02: 긴 작업을 맡긴 동안 발신 세션은 자기 일을 하고, 늦은 답을 중복 없이 회수한다.
- A16-03: 같은 기능 표에서 priority·wake·첨부·회신·결과 입력의 CLI/MCP 차이를 전수 확인한다. 미지원은 명시한다.
- A16-04: 샌드박스 Codex가 첫 답장부터 가능한 경로를 사용한다. CLI 거부 후 모델이 임의로 대체 명령을 찾는 과정을 기본 절차로 삼지 않는다.
- A16-05: 자동 수신 능력이 사라지면 미독 안내와 회수 경로가 살아 있다. 도구 숨김 때문에 답을 영원히 못 읽는 경우를 재현한다.
- A16-06: 후속 질문을 일반 세션과 serve 각각에서 실행하고 네이티브 세션 ID·기억 유지 여부를 대조한다. 한 경로의 성공으로 다른 경로를 통과시키지 않는다.
- A16-07: 수신 대기 중 취소·시간 초과·동시 답변·여러 부분 회신을 검사한다. 대기 종료가 상대 과제를 중복 실행하지 않는다.
- A16-08: 두 발신자가 같은 협력자에게 동시에 요청하고 각자 후속 질문을 보낸다. 문맥 공유 단위·직렬화·퇴출 후 기억 소실·독립 검토 격리를 각각 확인한다. 설정한 용량만큼 모두 작업 중일 때 새 발신자를 추가해 요청 유실·새 워커 즉시 회수·미실행 성공 답변이 없는지 검사한다.

## 비용과 되돌리기

동기 질문은 호출 제한 시간을 소비하고 여러 회신 중 무엇을 답으로 볼지 정해야 한다. 동적 도구 목록은 하네스 캐시와 호환성 비용이 있다. 기존 송신·수신을 유지하고 질문 계층을 제거할 수 있게 하되 진행 중 request ID와 답을 계속 조회할 수 있어야 한다.

## 미결 매개변수

질문의 기본 대기 시간, 부분 회신과 최종 회신의 표현, warm 문맥의 업무별/발신자별 공유 단위와 회수 정책, 도구 노출 갱신 방식, 기존 도구 이름의 호환 기간은 아직 결정하지 않았다.
