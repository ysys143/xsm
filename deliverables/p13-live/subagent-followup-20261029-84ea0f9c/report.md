# 동일 factory 자연 목표: native subagent 후속 표본

새 고정본에서 **기본 auto의 exact unsupported 8건 → stored/mcp-inbox → 실제 상대 claim/ACK 8건**, 원 질문 ID를 가리키는 **최종 수학 reply 3건(outcome=succeeded)**을 관측했다. 상대 incoming 파일 entry 읽기 4회에서 실제 caller ownership과 content SHA가 manifest와 일치했다. shared-MCP는 계속 미확보다. 이번 positive 교차 메시징을 공유 process 증거나 전체 계획 완료로 확대하지 않는다.

CLI는 `codex-cli 0.164.0`, 관측된 기존 profile의 app-server binary는 0.165.0이다. source `/private/tmp/xsm-native-integration-frozen-tsucjdu0`의 제공 manifest 315개/primary 135개를 대조했다. 같은 1 parent/2 native child, 같은 자연 goal·factory argv/env·기록 proxy를 유지하고 source/root/출력만 바꿨다. refs·도구 순서·fallback 힌트는 추가하지 않았다. 평가 CLI 1회, 조건 자동 재시도 0, 실제 CID/PID/home 초기 등록 setup 3회다.

모든 ask/send 호출은 wake를 생략하거나 auto였고 canonical message.wake=True였다. native queue의 정확한 unloaded-subagent -32600이 기록됐으며 top-level delivery_route=mcp-inbox로 저장됐다. native queued/wake evidence는 모두 false다. ID·원문과 immutable identity/digest를 유지했다. ACK는 실제 xsm_ack의 token/ID와 해당 receiver를 대조했다. token/ACK 원시 값은 공개하지 않는다. reply_to는 각 원 질문 ID와 일치하며 질문 인덱스에 실제 reply 1개씩 최종 succeeded가 있다. 수학 답의 최소 발췌와 각 hash는 summary에 있다.

MCP process는 부모/하위별 3개로 분리됐다. 부모 xsm tools/call은 0이며 질문·본문·ACK를 부모나 proxy가 중계·주입하지 않았다. proxy는 byte 기록/전달뿐이고 provider의 실제 thread metadata를 바꾸지 않았다.

오류/한계도 보존했다. `xsm_files` 1회가 FileNotFoundError로 실패했으며 호출 인자와 오류는 summary와 private raw에 있다. 이후 실제 incoming entry 읽기 4회의 content SHA/owner 일치를 확인했다. 이 최초 실패를 없었던 것으로 만들지 않는다. profile config hash drift는 실행 전후 관측값 그대로 기록하며 변경 주체는 미확정이다. 기존 실패 원본은 바꾸지 않았다. native 기본 지침·feature·권한·profile 설정을 평가자가 변경하지 않았다. frozen source는 전후 일치했다.

raw/state는 `/private/tmp/subagent-followup-p41ahv_v`에 보존한다. 소유 native wrapper/Codex/proxy/MCP의 PID·시작 시각으로 종료를 확인했고 잔여 known process는 0이다. 추가 모델 실행이나 source 수정 없이 종결했다.
