# V5 independent-input bounded upload participant

New v5 files only; the own v2/v3 sources and evidence remain unchanged. The upload
implementation uses the public v5 contract and our own v3 JSON-RPC transport.
It imports no xsm module or SDK. The public checker and our fixtures are separate.

```sh
python3 -B examples/independent-participant/verify_v5.py \
  --server-executable /absolute/path/to/frozen-xsm \
  --bundle /absolute/path/to/public-v5-bundle \
  --checker /absolute/path/to/public-v5-bundle/conform-host-protocol.py \
  --output ./new-v5-evidence

python3 -B examples/independent-participant/regression_v5.py \
  --server-executable /absolute/path/to/frozen-xsm \
  --bundle /absolute/path/to/public-v5-bundle \

  --output ./new-local-evidence.json
```

Executable and checker selection are trusted operator settings. Peer messages and
local JSON requests do not choose an executable or argv. The server argv suffix is
always `protocol serve --stdio`, with no shell. The public checker is executable
Python code; do not supply it from an untrusted message. Every child receives an
isolated HOME/XSM_HOME/cwd and only PATH/LANG/TMPDIR from the supplied environment.
Environment filtering is not an OS sandbox. Runners require new output names.

```python
from participant_v5 import Peer, UploadPlan, server_command

peer = Peer(server_command(operator_selected_absolute_executable))
try:
    peer.initialize()
    owner = peer.open("fixture-owner")
    # receiver_ref comes from an explicitly participating fixture peer.
    plan = UploadPlan.snapshot(
        "ref:" + receiver_ref, "fixture-request", "Original body",
        [{"name": "already-read.bin", "data": caller_supplied_bytes}],
    )
    prepared = peer.prepare_files(owner, plan)
    # Preparation alone sends no body and performs no ACK.
    # The host explicitly chooses whether to call xsm_send/xsm_ask afterward,
    # retaining the original ID/text and prepared.result["manifest_id"].
finally:
    peer.close()
```

`UploadPlan.snapshot` copies bytes/bytearray/memoryview into immutable byte
snapshots, hashes them and retains their metadata. It accepts no source path and
never reads a file. The public per-file 1 MiB, aggregate 4 MiB and 16-entry bounds
are enforced before RPC. Optional source_version is a caller label, not provenance.
A plan retains original target/request ID/body/explicit fallback/previous manifest.

`require_uploads` checks all three advertised v5 limit fields and native integer
types before helper use. This implementation supports the v5 constants; missing
or different limits raise UploadUnavailable locally, without pretending the
server advertised support. Low-level `upload_open/write/commit/status/abort`
methods expose the five host methods. Raw invalid-argument tests deliberately
use generic `call` to reach server validation instead of being blocked locally.

`prepare_files` opens/resumes matching metadata, honors returned per-entry byte
offsets, writes at most 192 KiB decoded per chunk and commits. It validates request
binding, progress, write correlation and frozen commit/no-body evidence. It never
automatically sends, acknowledges, reconnects, aborts on an ambiguous error, or
retries unknown body delivery. On error, keep the plan and use status or an explicit
new preparation attempt. A commit may index a frozen manifest before capability
failure; inspect structured attachment_error/status, not a parsed display string.

`Prepared.upload` is the completion token when available, or None for an existing
frozen reopen. It is execution-local and is not a durable ID. Status/reopen by the
original request ID is the recovery path. Under slot pressure the observed server
evicts completion-token metadata before admitting a replacement; active handles
remain bounded at 16 and the frozen index survives. The public text does not define
minimum completion-token lifetime or eviction order, so do not rely on indefinite
commit replay or infer lost frozen bytes from an unknown upload token.

The CLI accepts the same generic local JSON requests and `$session`/`$notification`
conventions as the own v3 participant:

```sh
python3 -B examples/independent-participant/participant_v5.py \
  --server-executable /absolute/path/to/frozen-xsm
```

Public `uploads` checks include their own generated 4 MiB fixture; our independent
fixture uses different generated bytes and additional range, budget, slot, abort,
EOF, capability recovery and outgoing-copy checks. The v3 regression wrapper
reuses only our unchanged v3 scenarios with the new own participant. No earlier or
parent result is imported as implementation evidence. All UI responses are
explicit synthetic fixtures, never real human approval.

Local tests use a mock transport and four in-memory defects in our own upload
helper: mutable snapshots, missing-extension acceptance, lost resume offsets and
lost write-offset checks. These do not certify server internals. Wire artifacts
contain only generated fixture bytes and temporary handles. The inherited 4 MiB
output-frame guard and five-second RPC deadline are client/verifier limits, not a
claim about total process memory or a larger engine upload quota. Full legacy
manifest/reference schemas, quota/retention faults, native admission and actual
30-minute expiry are outside this run's completed coverage.
